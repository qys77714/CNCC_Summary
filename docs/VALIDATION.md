- LLM 429 重试和响应缓存；截断响应、缺失片段 ID 和无效引用拒绝。
- 大幅“纠错”回退原文；真实 HTTP 客户端搭配 MockTransport 的完整总结/报告流程。

- 姓名修改不重跑纠错；重建失败不会把旧纪要作为当前结果。

模拟测试只验证软件逻辑，不证明真实识别精度、真实模型遵循 JSON 的稳定性或实际性能。

## 必须在服务器补做的验证

当前尚未验证：真实 Qwen/ForcedAligner 权重加载、4090 峰值显存与吞吐、四卡长时稳定性、可选 pyannote 实际聚类效果、你的 LLM 服务格式兼容性和真实输出质量。

推荐先在 `video/` 创建一个临时短样本，避免全场跑完才发现配置问题。以下命令仅在你准备好模型与 API 后执行：

```bash
# 服务器安装了系统 ffmpeg 后，替换为一场真实视频名。
# 取非开头的两分钟，可避开片头音乐，文件不要放进默认 video/ 扫描目录。
mkdir -p samples
ffmpeg -ss 00:10:00 -i 'video/某场真实会议.mp4' -t 120 -vn -ac 1 -ar 16000 samples/smoke.wav

.venv-server/bin/cncc-minutes doctor --llm
GPU_DEVICES=0 .venv-server/bin/cncc-minutes run --file samples/smoke.wav
```

检查相应 `minutes.md`、原始/校正逐字稿和 `quality.json`：

1. 对照音频核对开头、中间、结尾的专业词、数字和否定表达，确认没有明显丢句。
2. 检查引用位置，确保摘要真实反映引用原文；不存在的责任人和期限不能被编造。
3. 再执行一次同样命令，观察 ASR/API 缓存是否复用，而不是重新计算全部片段。
4. 观察 `nvidia-smi`、主机 RAM 与磁盘，必要时将 batch 改为 1、片长改为 15 秒。
5. 启用声音分组时，检查实际说话人切换，人工确认姓名后再更新映射。
6. 最后用 `run` 处理全部视频。四台服务器部署时，各自使用唯一分片编号。

如果短样本调用中断，直接重跑即可；不会丢掉已完成片段。不要用模拟示例的成功来代替这一轮服务器验收。
