# 设计依据与当前输出目标

初版参考了飞书智能纪要的总结、章节、待办和逐字稿能力。[飞书帮助](https://www.feishu.cn/hc/zh-CN/articles/244959839578)、[妙记产品页](https://www.feishu.cn/product/minutes)。

当前目标已调整为**按清晰主题组织的详细技术总结**。最终写作由 LLM 根据内容安排，不再沿用会议资料、导航、待办、时间章节、引用和附录等栏目。

## 为什么改流程

旧流程把固定时间窗口映射为固定栏目，然后反复合并压缩。时间窗口跨越报告边界时会割裂主题；重复的栏目会占用阅读空间，多次压缩也会丢掉方法细节和限定条件。只删掉 Markdown 模板，无法改变内部过度压缩的材料。

新版将阅读、规划和写作分开：

1. 分批阅读时保留实质内容和细节，不预设最终文档栏目。
2. 全场规划只归并主题目录，同时确保材料没有遗漏或重复分配。
3. 按主题读取详细材料写作，长主题续写，全文保留各批正文。
4. 默认允许适量背景解释，要求区分通用解释与会议主张。

内部 JSON 用于控制材料分配，不规定最终 Markdown 的子标题。模型可以为不同主题采用不同组织方式。

## 仍然需要约束的部分

允许知识补充不意味着可以补写录音缺失内容、虚构实验、推断人名或引用凭记忆编出的论文。正文不强制列核对清单；不能确认且不影响主旨的专名可省略，关键条件与不确定性则融入对应讨论。

用户提供的旧纪要后半段存在词表重复。代码默认关闭 ASR 词表注入，并在总结输入中保守排除明显词表回声，避免把一串关键词写成虚假的技术报告。该处理不能找回已经遗漏的演讲。

## ASR 组件

继续使用 Qwen3-ASR-1.7B 和可选的时间对齐模型，保留小片段识别与多 GPU 并行。模型选择和下载说明见 [MODELS.md](MODELS.md)，官方推理接口来源于 [Qwen3-ASR 项目](https://github.com/QwenLM/Qwen3-ASR)。

这套主题阅读与写作流程是本项目的工程设计，不声称复现飞书的内部实现。
