# 架构、数据与缓存

## 流程

```text
扫描媒体 / 可选多服务器分片
              ↓
主进程：GPU 共享任务队列
              ↓
每张 GPU 一个 spawn 进程，持有常驻 ASR/对齐模型
  源视频 SHA-256 → 16kHz mono PCM → 停顿分析 → 连续音频分片
  → 小批次 ASR + 词对齐 → 可选整场声音分组 → 原始转写
              ↓                         GPU 开始下一个视频
主进程：多个视频并行执行 LLM 整理
  纠错（带前后文）→ 局部章节提炼 → 有界的多层合并
  → 引用校验 → 固定模板 Markdown + SRT + JSON
              ↓
整批索引、成功/失败清单
```

ASR 子进程开始后先隔离 `CUDA_VISIBLE_DEVICES`，再导入 torch 和 qwen_asr；使用 spawn 避免 fork 后 CUDA 上下文不安全。每张 GPU 最多一个工作进程。相同主机共享动态视频队列，不要求视频时长一致。GPU 工作者异常退出时，主进程会标记未完成任务；正常的单视频异常不会终止其他工作者。

LLM 在主进程的线程池中运行。一个视频内部依次纠错、生成各章节，再合并；多个视频可以并行。所有视频共享 HTTP 客户端、并发信号量和请求开始速率限制。ASR 完成后即可开始 LLM，不必等整个批次识别完。

## 音频与时间轴

- 提取首个音轨，16kHz、单声道、16-bit PCM。源视频不修改。
- ffmpeg `silencedetect` 获取停顿，最多 25 秒一片，优先在目标切点前约六秒窗口内选停顿中心。
- 使用整数采样位置描述半开区间，不用浮点秒反复取整，因此整个音轨不重叠、不漏采样。片段内部无长停顿时会在上限切开，边界附近的词仍可能识别不准。
- ASR 和对齐分片共享同一原始音频；对齐时间加上分片起点得到全场时间。
- 将词时间与声音分组按最大重叠匹配，再聚合为可阅读的段落。ASR 的标点/空格不会因对齐的文字规范化而丢失；不一致时保留整个原文并回退片段时间。
- `s000001` 这样的 ID 在单个转写结果内唯一。ASR 结果变化可能使编号变化；不同运行版本的引用不要混用。

## 缓存层级

| 层级 | 主要指纹 | 保存位置 |
| --- | --- | --- |
| 音频 | 源视频完整 SHA-256、采样格式版本 | `audio.json` + `audio.wav` |
| 分片 | 音频指纹、最大时长、切分版本 | `chunks.json` |
| ASR 片段 | 分片规划、模型指纹、语言、生成上限、时间戳选项、术语表 | `cache/asr/<key>/<index>.json` |
| 声音分组 | 音频、模型元数据、人数 | `speakers.json` |
| 纠错/章节/合并请求 | 服务地址、模型、温度、输出上限、完整提示和资料、schema | `cache/llm/<hash>.json` |
| 最终纪要 | 原始转写、模型配置、背景、预算、提示、人工姓名 | `summary.json` |

源视频哈希是完整流式读取。模型指纹为文件路径清单、大小、修改时间和小配置哈希，不对每个数 GB 的权重重复计算完整哈希。模型目录复制后元数据变化可能导致重新识别，这是保守行为。每个 API 响应只在成功解析且通过业务检查后缓存；超时失败、输出截断、非法引用不会进入成功缓存。

写入 JSON/Markdown 使用同目录临时文件和原子替换。输出根通过文件锁排除两个运行同时修改；它不是跨节点任务队列。不同服务器用独立输出根，人工汇集结果。

## 质量约束

纠错校验要求输入与输出的 ID 列表完全相同且同序。局部改写如果改变数字、常见关键否定表达、长度变化过大或整体相似度过低，会保留原文、标记疑点并保存建议版本。数字转写规范化有时也会被保守拦截，需要回听确认。该检查不是完整语义校验。

每条摘要必须至少引用一个原始片段。局部摘要只能引用本组输入；合并摘要只能引用下层保留的原始引用。引用 ID 存在性会检查，语义支持程度仍须人工确认。

输出超过字符预算、finish_reason 不是 stop、缺字段或多字段等都会失败或重试。失败时保留已完成缓存，记录错误，不会替换成模板假纪要。完整章节内容保留在 `summary.json` 和最终 Markdown，降低层层压缩带来的细节损失。

## 主要源码

| 模块 | 职责 |
| --- | --- |
| `config.py` | `.env`、类型与参数校验 |
| `media.py` | ffmpeg 导出、静音分析、整数采样切分 |
| `asr.py` | 官方模型适配、OOM 分批恢复、声音匹配 |
| `llm.py` | 兼容服务调用、全局限流、重试、响应缓存 |
| `prompts.py` / `schemas.py` | 提示约束和结构化输出 |
| `summarize.py` | 纠错、审计、分层总结、引用检查 |
| `pipeline.py` | 多 GPU 队列、阶段衔接、失败隔离 |
| `report.py` | Markdown、字幕、质量文件及索引 |
| `storage.py` | 指纹、原子文件写入、状态与独占锁 |

扩展其他 ASR 时，应返回相同的文本、词时间和分片字段；扩展 LLM 服务时，优先通过 `.env` 的兼容配置完成。不要在没有验证加载 API 的情况下替换模型类型。
