# 主题总结架构

## 处理路径

~~~text
媒体 → 标准音频 → 短片段 ASR / 可选时间对齐与声音分组
                         ↓
                  原始转写（不经 LLM 校正）
                         ↓
              明显词表回声 / 相邻整段重复过滤
                         ↓
           分批阅读，保留详细主题材料及内部段落编号
                         ↓
            全场主题规划：跨窗口归并、逐条材料分配
                         ↓
              各主题自由 Markdown 写作 / 续写
                         ↓
                合并正文 → minutes.md
~~~

移除了旧流程中的逐字稿纠错、固定八类摘要字段、时间章节模板和全场反复压缩。保留已有 ASR、多 GPU 任务队列、限流、失败隔离和缓存。

## 阅读与全场主题规划

阅读窗口只用于控制 LLM 输入大小，不是最终主题边界。一个窗口可提炼多个主题的材料，同一主题也可跨多个窗口。

阅读响应采用内部 JSON：每条材料有标题、详细内容和原始段落编号。程序检查编号确实属于该输入窗口；这只能检查编号存在性，不能证明语义准确。阅读阶段只提取会议内容，不添加背景知识。

规划阶段仅输入材料目录与短描述，要求模型根据整场内容决定主题的数量、名称、顺序与写作范围。每条材料必须恰好分配给一个主题，遗漏、重复或新增编号会被拒绝。目录过大时分层合并目录，详细材料正文始终保留，不随目录规划压缩。

## 详细主题写作

每个主题使用其全部详细材料，并在预算允许时补充对应原始转写片段。写作请求直接返回 Markdown，不使用 JSON response_format，也不转义 Markdown 内容。

没有固定的“背景、方法、结论”子标题要求。模型可按内容使用段落、小标题、比较表、公式或示例。长主题分批续写：后续请求携带已写末尾和标题列表，避免重复开头，并保留各批全部正文。最终仅连接全文标题、可选自然导语和各主题正文，不再执行高度压缩的全场综合。

默认允许适量使用通用知识帮助解释。补充必须自然区别于会议观点；不能编造实测数字、人物/论文归属、最新事实或缺失报告。SUMMARY_ALLOW_KNOWLEDGE=false 时关闭补充。SUMMARY_STYLE 作为自然语言写作偏好传入。

## 输入噪声与 ASR

默认 ASR_USE_GLOSSARY=false，不把词表注入 ASR。启用时改变识别指纹，相关 ASR 缓存自动失效。已经受污染的转写可以重新总结以去掉明显词表回声，但真正漏掉的演讲需要重新识别或检查源音轨。

总结输入过滤只排除可明确匹配词表、缺少实质说明的长清单，以及相邻整段精确重复；不修改原始转写。其余闲聊、串场和不完整内容交由阅读提示排除。过滤不是声学 VAD，不能断言被识别为回声的时段一定没有语音。

过滤记录保存在 summary.json 的 excluded_segments 中，不进入最终正文。原始 ASR 警告仍留在原始结果，最终不再生成独立质量栏目。

## 缓存与迁移

- 音频：源视频完整 SHA-256、标准音频格式版本。
- 分片：音频指纹、切片设置。
- ASR：分片、模型元数据、语言、生成设置及实际是否注入术语。
- LLM：服务身份、完整提示、输入、schema/输出模式；JSON 与 Markdown 请求区分缓存。
- 总结：原始转写、提示版本、输入预算、姓名映射、背景、写作偏好和知识补充开关。

新版格式标识为 thematic-v2，旧结构化摘要和校正稿不会复用。JSON 和 Markdown 仅在正常终止、解析及业务验证后保存为成功缓存。失败的写作请求保留此前成功请求，重跑时接着处理。

每次重建将旧 minutes.md 保存为 minutes.previous.md，只有 report_status.json/status.json 标示 complete 才属于本轮成功。文件使用临时文件和原子替换；同一输出根有独占锁。

## 并行

每张 GPU 一个 spawn 进程，隔离 CUDA 可见设备后才加载模型，多视频共享动态任务队列。LLM 在主进程线程池中同时处理多个视频，共享请求并发和 RPM 限制。单个视频内依次阅读、规划、写作，便于稳定缓存和串联主题。

多台机器使用同一固定视频集合的排序轮转分片，各自独立输出根。该模式没有跨主机动态调度；同一 LLM 账户的总并发和 RPM 是各服务器之和。
