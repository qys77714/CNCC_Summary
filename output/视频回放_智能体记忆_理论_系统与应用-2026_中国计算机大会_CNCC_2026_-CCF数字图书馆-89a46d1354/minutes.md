# 从符号记忆到参数化记忆：智能体记忆的机制、个性化与多模态前沿

智能体记忆正从外挂符号系统走向参数内生，并延伸至个性化与多模态场景。全文围绕记忆形式、构建与检索、参数化写入、持续学习及可信性展开，梳理报告中的技术路线、实验观察与开放问题。

## 智能体记忆的研究框架：科学问题、记忆形式与应用价值

开场把“记忆”放在智能体研究的核心位置，而不是把它仅仅看作一个工程模块。报告首先追问两个基本问题：**记忆是什么，为什么值得研究**。在大模型出现之前，人工智能领域就已经在探索能否让机器记住信息；如今，随着模型能力和应用场景扩展，记忆又成为持续学习、个性化建模和复杂任务执行的基础能力。报告对记忆的定位是：它既是一个前沿科学问题，也是模型能力继续提升的基础设施。

### 两类记忆：参数化与非参数化

报告将记忆大体分为两类。

| 类型 | 基本含义 | 特点 |
|---|---|---|
| 参数化记忆 | 把信息真正写入模型参数，使模型在参数层面“学会” | 记忆沉淀为模型能力，是本次报告的重点 |
| 非参数化记忆 | 依赖大量上下文和工程化记忆系统保存、调用信息 | 当前工业界较主流、较实用，已有较多实践案例 |

本场重点讨论参数化记忆。报告明确区分这两条路线，是因为二者的问题结构不同：非参数化记忆更多涉及上下文组织、检索、存储和系统工程；参数化记忆则直接追问模型能否把经历转化为自身能力。非参数记忆的高效构建和个性化案例由后续报告展开，本主题只把它作为对照，用来界定参数记忆的位置。

这也解释了报告为何强调“前沿探索”。参数化记忆并不是一个已经完全成熟的工程方案，其中一些方向目前效果未必好、方法也未必稳定，但作为通向持续学习的路径具有探索价值。报告因此会同时讨论相对成功和不够成功的案例，而不是把参数记忆包装成现成答案。

### 生物记忆的启发：记忆不是单一存储

报告用脑科学和认知科学中的案例说明，记忆并不是一个简单的“存进去、取出来”的过程。亨利·莫莱森因疾病只能保留短期信息、缺乏长期记忆能力，成为研究记忆系统的典型案例。围绕这类案例，研究逐渐发现，生物体的记忆包含多种功能系统：海马体可能承担快速编码功能，皮层具有一定的长期记忆能力，短期记忆可以转化为长期记忆，某些类型的记忆甚至可能通过生物传承机制传给下一代。报告提到，对某些事物或生物的恐惧可能通过这种机制影响后代。

这些现象指向一个关键认识：生物体在漫长进化中形成的是一套**分层次、可转化、可传承的记忆功能系统**，而不是单一存储介质。报告借此反观当前 AI 的不足：模型可以在上下文中临时记住信息，也可以经过预训练获得知识，但短期记忆如何沉淀为长期经验、经验如何进一步转化为模型能力、能力如何在持续演化中积累和传承，仍然没有很好解决。

因此，报告希望机器系统实现的不只是“记住上下文”，而是：短期记得住，长期沉淀为经验，并在不断进化中形成可传承的记忆。记忆不应停留在上下文窗口里，而应尽可能沉淀到模型能力中。

### 为什么记忆是持续学习的关键

报告把记忆视为 AI 模型持续学习的关键步骤。模型要持续学习，首先得记得住；如果告诉 AI 一件事，它都记不住，就谈不上融会贯通和积累经验。报告用“智能源于学习”概括这一逻辑：神经网络本身具有可塑性，上下文学习能够让模型见到新信息后适应、改变和提升能力，而记忆可以帮助大模型或智能体巩固相关信息、积累经验。

从人工智能的发展路径看，过去主流做法是通过预训练让模型学会知识，学完之后再通过上下文补充信息。报告进一步追问：能否让“上下文进参数”这一整套链路转起来，形成持续学习与演化的机制？从通用原理看，这涉及新知识写入与旧能力保持之间的平衡，也是持续学习长期关注的核心矛盾。报告没有把问题简化成“加一个记忆模块”，而是把它放在模型能力演化的层面上讨论。

报告还提醒，记忆研究并不只属于人工智能。脑科学、认知科学、心理学都在研究记忆，包括环境对人机记忆的影响、创伤后遗症等问题。生物记忆系统与大模型有共同的基础性问题，这使得记忆成为一个适合跨学科探索的方向。

### 应用价值：从 AI 科学家到个人助手

记忆的实用价值体现在多个落地场景中，报告举了三类例子。

- **AI for Science 中的“AI 科学家”**：AI 需要帮助执行科学实验，因此要记住实验流程、实验过程，并在执行中不断沉淀经验，做到举一反三。没有记忆，实验经验难以跨任务积累。
- **个人助手**：手机上存储大量个性化信息，个人助手可以利用这些信息帮助用户做日常规划。个性化场景强调“千人千面”，记忆是关键模块。
- **科研工作**：AI 可以帮助科研人员记录想法、工作积累以及实验失败或成功的案例，持续积累并提高工作效率。

报告还引用强化学习先驱、图灵奖得主的观点：让 AI 像婴儿一样自主进化、真正持续学习，记忆是其中非常重要的环节。这一观点把记忆从“应用功能”提升为“智能体自主演化的组成部分”。

总体来看，这一主题确立的框架是：先区分参数化记忆与非参数化记忆，再把记忆作为持续学习的科学问题，回到生物记忆的多层次功能中寻找启发，最后用 AI 科学家、个人助手和科研工作等场景说明其应用价值。参数化记忆因此既是一个尚在探索的前沿方向，也是理解智能体能否持续学习、积累经验并形成长期能力的关键切入点。

## 外部符号记忆的产业实践与高效构建

报告的基本判断是：符号化记忆是当前工业界最主流、最实用的记忆形态。所谓符号化或非参数化记忆，可以理解为把智能体在工作、学习、生活中积累的经验放在模型参数之外，用文本片段、结构化条目、索引或指针来组织；从通用原理看，它与直接改动模型参数是两条不同的技术路线。材料提到，OpenAI、Anthropic、记忆张量等公司或团队已经开发了大量非参数化符号记忆系统，使用 GPT 等智能体时已经在享受记忆带来的红利。一个典型场景是：用户今天关心物理科研怎么做、某道物理题怎么解，过一段时间又出现新主题；这些曾经的经验不断累积到记忆库，以符号化上下文的方式组织起来。

但“有记忆库”不等于“记得好”。报告把核心问题概括为“到底应该记什么”：每个人每天接收的信息量很大，模型收到的上下文也很大；如果直接把原始对话堆进库，冗余会迅速膨胀。需要从大量冗余上下文中提取高度密集、有效的信息，让智能体形成长期记忆积累。这个问题决定了记忆系统不能只追求容量，而要在准入、组织、整合和读取几个环节同时做取舍。

### 成本瓶颈：构建、维护与读取

报告把长期记忆的 token 成本拆成三个阶段。这个拆法很关键，因为它解释了为什么“记忆”在论文里常显得有效，落到部署却可能很贵。

| 阶段 | 现有代表性做法 | 主要成本来源 |
| --- | --- | --- |
| 记忆构建 | 处理完整用户对话记录，调用大模型做事实提取、摘要生成或结构化更新 | 输入是原始记录，写入开销大 |
| 记忆维护 | 反复整合记忆，在线检索、对比、合并和冲突消解 | 在线整合消耗时延 |
| 记忆读取 | 先检索；效果不好再多跳检索、补证据，把多轮结果拼接 | 多次调用大模型，上下文膨胀 |

报告用“贪心式固化”形容当前一些代表性外部记忆系统的构建策略：每一轮 user-agent 交互到来，都调用大模型对原文做抽取和固化，不区分这一轮信息是否值得记。长对话中这样做的 token 开销很大，严重制约实际部署。材料提到，若干典型记忆系统在构建阶段平均约需消耗 1626k 个 token；它们虽然能提升下游任务精度，但资源消耗很高，其中记忆构建阶段是最不可忽视的成本瓶颈。因此，“如何高效构建记忆”成为第二个核心问题。

### 缓存连续性：记忆系统不能只看库内 token

还有一个容易被忽略的成本维度是 KV Cache。从通用原理看，KV Cache 缓存历史 token 的键值状态，避免每一步重复计算；如果记忆系统频繁改写上下文前缀，缓存可复用的部分就会减少。报告指出，记忆有时会把上下文存储在 KV Cache 中；把上下文移到记忆库，表面上减少了 prompt 资源开销，但若导致 KV Cache 命中率下降，推理成本反而可能上升。也就是说，想让上下文变短、存到记忆里，不等于成本一定低。

报告用 ReAct 范式举例：输入 prompt 后，智能体经过 thinking、tool call、反思，这是经典的“推理—行动”循环。中间形式非常复杂：不同任务的前缀 prefix 可能不同，环境反馈也可能很复杂，例如网页任务会返回一堆 HTML 代码。这些形式变化会让进入记忆系统的上下文发生很大变化，导致 cache 命中率下降，增加延迟和成本。一个简单思路是构建稳定的 stable prefix，做轻量的形式转换，把某种 KV 形式转成经典形式，从而提高命中率。报告展示的结果称，这种做法可以降低开销；无论与经典记忆系统还是上下文压缩方法相比，都能提高效果。这里的主线是：记忆系统与 KV Cache 要一起优化，保证记忆上下文连续，命中率提高后效率才会上来。

### Light Memory：先压缩、按主题组织、离线整合

Light Memory 是报告详细介绍的第一篇高效记忆构建工作。它的核心不是把完整上下文直接堆进库，而是在记忆准入阶段先做预压缩、去冗余，再按主题组织记忆，并把耗时的记忆整合移到离线阶段，以降低构建开销和时延。

具体有两个压缩机制。第一是基于 entropy 的压缩器：用一个通用模型，通过 cross entropy 判断模型能否预测对话接下来的 token。若 entropy 高，说明模型难以准确预测，该 token 信息量较大，应保留；若 entropy 低，说明模型比较 confidence，对应输出信息量低，可以删除。第二是 token 级分类：用一个小语言模型逐个 token 判断删除还是保留。报告举例说，像“AI student”“memory framework”这类信息量较高的词会被保留。经过这两个模型完成上下文预压缩和冗余删除后，Light Memory 按主题构建记忆，而不是按输入轮次或固定长度切分。一段对话可按语义关联切成三四个主题；展示的例子被切成三个主题：第一个主题总结出“用户是一个 AI student”，第二个主题是“用户目前的活动是什么”，各主题分别形成记忆保存。

另一个重点是记忆整合的离线化：系统保存一个 memory buffer，记录记忆发生了哪些更新；buffer 存满后，再对整个记忆做一次离线整合。这样可大幅降低记忆构建开销和延迟。讲者用“很惊喜”形容实验结果：该方法既节省开销，又能提升 memory 的效果。不过讲者也指出，基于熵和语义信号的筛选本质上仍是在 token 维度对语义信号做判断，并没有完全解决“记什么”的问题。

### Simple Memory：写入端结构化压缩与多索引读取

第二篇工作是 Simple Memory。报告概括它关注两端：写入时提高信息密度，读取时控制证据规模。这个概括也点出了它与 Light Memory 的差异：两者都做结构化语义压缩和记忆准入，但 Light Memory 更强调压缩与主题化，Simple Memory 更强调写入端的规范化表达和读取时的多索引规划。

在写入阶段，Simple Memory 对输入做结构化的语义压缩，包括冗余过滤、指代消解和时间归一化。报告举例：原始输入经处理后形成“用户计划于 2026 年 10 月 20 日前往杭州”“此次杭州行的同行者是小李”等记录。随后再做在线的语义整合，把多段离散对话合并成完整语义，例如合并为“用户计划于 20 号与小李前往杭州”，以统一形式存入记忆系统。

Simple Memory 还建立多种索引：语义索引，例如标识整条记忆的语义类别是“出行安排”；词法索引，抽出“小李”“用户”等具体词建立索引；元数据索引，例如“十月份”等时间信息。读取阶段的例子是查询“用户十月份和小李有哪些出行安排”。大模型先做检索规划，决定从哪些索引查什么：语义索引查“出行安排”，词法索引查具体人物，元数据索引查具体时间；然后合并三种索引的检索结果，并按索引 ID 去重。这样可以用更精简的证据来生成回答。报告把 Simple Memory 与 Light Memory 对比为：两者都做结构化语义压缩和记忆准入，但方式不同。

### Lean Memory：按信息性质分型，受控写入与选择性演化

报告介绍的第三篇工作是其团队提出的 Lean Memory；材料中也出现 Learn Memory 的写法，讲者解释这个词取“瘦”的意思，用以体现这套方法在记忆体积上的取向。它的核心是按信息性质采用不同的压缩与存储策略，而不是对所有对话用同一种摘要方式。

报告把用户与智能体的对话信息分成几类。低信息内容，例如长期寒暄，缺少长期保留价值，不应写入记忆系统。稳定的用户表示与偏好，例如用户目前就职于一家小创业公司、是销售专员，这类长期稳定属性存成 profile memory，可以紧凑表示，且不容易更新。变化的事件，例如“今天下午四点要开会”“10 月 20 日跑了一场马拉松”，这类 event memory 需要记录事件时间及对应的用户状态。需要精确记录的内容，例如信息密度很大的表格，尽量不压缩，而是存成指针，直接访问原文。因此，存储库实际包含 profile、event、record/recall 三类记忆，并用不同策略尽量以较少 token 保存且不损失信息。

系统流程大致如下。第一步是记忆准入：讲者观察到用户与 assistant 的聊天记录中，assistant 侧回复往往很长，但用户说的话才更能表示个人偏好；因此准入阶段删除所有 assistant 回答，仅保留用户较简短的对话，以减少记忆构建阶段的大模型调用并去除冗余噪声。第二步是主题切分：计算各段对话之间的 embedding 相关性，在相关性低谷处切分 topic；相关性低谷表示用户可能换了话题。第三步是记忆分类与写入：用较小模型把切分后的 topic 片段分类为 profile、event 或 recall。若是 profile，调用 NLP 结构化抽取方法整理；若是 event，调用大模型总结 topic 并记录事件发生时间；若是 recall，则记录指向原文的指针，直接索引原文以降低记忆损失。第四步是记忆演化与整合：profile 和 record 基本不变，因此只对具有时间性的 event memory 做演化和整合，包括 topic 聚类与 memory merge，并采用局部增量、离线的整合方式；profile 和 record 不需要反复整合。第五步是检索：调用大模型做检索规划，分析 query 的约束限制、需要检索的 top k，以及应从哪个记忆库检索；随后从记忆库检索、对结果重排序，辅助最终 answer 生成。

讲者把方法总结为三步：受控的记忆写入——过滤低信息轮次、按主题分段、按信息密度和类型做“最小充分”的存储调度；选择性的记忆演化——只对 event memory 做局部增量与离线整合；查询规划驱动的按需检索。在通用 benchmark 上，讲者称该方法记忆效率高、节省构建阶段 token 消耗，并能提升记忆效果和最终生成文本效果，但未给出具体数字。

### 三条路线的共同点与边界

把三篇工作放在一起看，它们并不是在追求“更大的记忆库”，而是在几个环节前移控制点。写入前做准入和压缩：Light Memory 用熵信号与 token 级分类去冗余，Simple Memory 用冗余过滤、指代消解、时间归一化和在线语义整合提高信息密度，Lean Memory 则按 profile、event、指针分型，把寒暄等低信息内容挡在库外。组织上从“按轮次切”转向“按主题切”或“按信息性质切”。整合上尽量离线、局部增量，避免每一轮都调用大模型。读取上不再只做一次性相似度检索，而是先做检索规划，再合并多索引或按记忆库检索的结果。这些做法共同指向一个目标：让记忆的 token 成本从构建、维护、读取三个阶段同时下降，而不是只把 prompt 变短。

边界也很清楚。报告没有给出三套方法在统一评测口径下的具体数字；Light Memory 的讲者还指出，基于熵和语义信号的筛选本质上仍是 token 维度的判断。Lean Memory 在通用 benchmark 上的效果被描述为“记忆效率高、节省构建 token、提升效果”，但材料未展开具体指标。更重要的是，符号化记忆不管怎么组织，模型参数没有变化；它解决的是外部上下文的存取与组织，经验如何反哺模型参数属于另一条技术路线。另一个限制来自系统层：把上下文放进记忆库不等于成本一定低，KV Cache 命中率下降会抵消部分收益。因此，外部符号记忆的产业实践不能只看“记住了多少”，还要看写入是否受控、维护是否离线、读取是否有规划，以及缓存连续性是否被保住。

## 参数化记忆的问题定义、认知依据与内部机理

参数化记忆的起点是一个很直接的失效场景：智能体把经验写进记忆文件、符号库或上下文，任务当下可以完成；但一旦记忆文件丢失、上下文被清空，模型参数并没有发生变化，能力也随之消失，等于什么都没学到。报告把核心愿景概括为：让上下文中的信息真正沉淀到模型参数中，使模型在拿掉“说明书”之后仍然会完成任务。

这件事并不等同于把一段文本压缩后存起来。报告指出，参数化记忆至少要处理四个难点：从上下文中选择哪些信息；把信息写到参数的哪些位置；究竟修改哪些内容；以及如何把具体经历沉淀成可泛化的新知识，而不是只拟合当前任务。

### 人类学习类比：瓶颈在经验抽象与参数固化

报告用小孩学习滚筒洗衣机来说明问题。孩子先看说明书，知道先按哪个按钮、再怎么操作；操作过一次后，第二次甚至几个月、几年后都不必再看说明书，仍然会使用洗衣机。相比之下，当前 AI 的技能学习往往依赖一个额外的 skill 或一段上下文；一旦 skill 被丢掉、上下文被 flush，模型可能就不会了。人类能把说明书或上下文真正沉淀到大脑中，这正是参数化记忆试图补上的能力。

认知科学和脑科学文献提供了三层类比：

- **海马体快速编码**：海马体能快速获取和编码经历，类似大模型的上下文能力。报告认为，大模型已经具备这一层能力。
- **回放与交错学习**：人在睡眠或做其他事情时，大脑会重新激活相关经验，让旧知识与新知识协同学习。
- **固化与皮层整合**：知识不断固化，形成长期表征，皮层逐步整合新知识，并持续影响未来行动。

由此得到的判断是：当前智能体的执行、反馈、由环境形成经验等流程已经能够跑通；真正的瓶颈在于，如何把经历和经验变成成熟的、可迁移的经验，再把这些经验沉淀到模型参数中，并能依据已学知识指导下一次实践。这条链路才是持续学习的闭环。报告用幻灯片中的颜色阶段说明，参数化记忆工作本质上仍处在从“黄色”到“绿色”的环节，即从上下文经验走向参数内化。

### 外部符号记忆的瓶颈与视角转向模型内部

过去的一类做法是把经验写入数据库或符号化知识库，库中存储大量任务相关信息，也可以称为流程性知识或 procedure memory。外部记忆能够在一定程度上提升效果，但报告指出两个明显挑战：有时检索不到相关信息；符号信息本身也难以表征非常抽象的内容。

报告用苯环相关的例子说明后一个问题：让智能体扮演化学家去探究苯的化学式，它会到记忆库、知识库中检索内容，但库里的两条信息可能八竿子打不着，不可能产生关联；模型学习时也可能把两者当成完全无关的事物。实际使用智能体时，常见失败是找不到信息，或者找到了却没有用对。本质上，这属于外部检索失败，或者记忆本身缺乏抽象能力导致的失败。

因此，报告把视角从外部符号记忆转回模型内部，观察模型如何存储信息。已有机理可解释性工作表明，模型的 FFN 层和 attention 层已经存储了非常大规模的参数化知识；由于预训练规模，模型学到的很多知识甚至超越个体人类的理解。在某些高维空间中，不同信息的维度可能非常相似。这种相似性带来高度抽象化，可以扩大知识关联能力。报告用苯环与“蛇环”的类比说明：如果模型学得好，两个抽象信息在高维某个空间中可能相似，看到苯环时相关的“蛇环”就会被激活；类似现象在语言模型机理分析中多次被发现。

最坏情况下，如果模型既没见过“蛇环”也没见过苯环，FFN 层也没有存储这些信息，模型还有注意力这一隐式机制：在环境反馈过程中，attention 可以逐步把两者关联起来，后面的 attention head 再去发现相关性。纯符号方式也能做类似的事，但符号方式在某些层面的抽象维度没有那么高；注意力可以关注每一层、每一个位置，因此相对更有深度。从通用原理看，FFN 可理解为模型存储事实与模式的参数化通路之一，attention 更偏向按上下文动态建立关联；报告借用这一区分说明内部记忆的两种可能来源。报告还提到，早期已有一些把模型经验编码成参数的尝试，但这些工作仍依赖外部检索，背后缺乏系统化能力。

### 代表性路线：可插拔记忆块与超网络生成参数

报告举了几条代表性路线，它们的共同点是在 Transformer 大模型外围增加一份额外参数，并训练、学习这份参数。

- **Locus**：报告称其为腾讯今年上半年较早的工作。核心想法是把无法让参数真正学到的上下文转换成持久的参数记忆，同时面对灾难性遗忘问题，希望在参数更新、学到新东西后尽量不遗忘旧信息，并学到可泛化的新知识。做法类似 LoRA，也接近 test-time training：在模型中构建一个 native memory block，通过参数化更新的学习方式处理上下文。这个 memory block 包含记忆相关的写入、读取、擦除等操作。本质上，它是一个可插拔、可与模型架构融合的轻量化参数化记忆模块；有了上下文后，学习该模块即可实现较高效的持续学习和知识内化。
- **Delta Memory**：背景是上下文存储成本较高，而且信息并没有真正进入参数。它设计了一套 block 机制，位置和架构与前述工作略有区别；关键是在模型的注意力层等位置构建在线、可关联的记忆，把动态记忆更新与注意力耦合起来，也就是用 attention 来实现记忆更新。
- **Memory T 1.0**：报告提到这是近期放出的全新 native memory block 架构，并建议感兴趣的人关注。

报告还介绍了**超网络**路线：既然学习参数本身有成本，能否把原来依赖反向传播的学习过程变成前向传播过程？做法是额外训练一个 hyper network，专门根据上下文生成记忆参数。新知识进来后交给这个类似“参数生成器”的超网络，生成额外的 LoRA 类参数，作为参数化记忆。这样只需要一次前向传播，速度很快，可以高效内化参数；相比传统微调，成本更低、知识记忆学习更快。但这条路线难度也很大，效果需要大量调参。报告提到其团队也曾尝试训练额外的 hyper network，把长上下文转换成 LoRA 类参数。

### 形式化条件与相邻方向

报告把问题进一步形式化为：给定上下文，模型能够完成任务；希望有一天把上下文拿掉后，模型仍然能够完成同样的任务。就像孩子看说明书学会操作洗衣机，过两天把说明书拿走，仍然能操作好。也就是通过上下文真正进入参数的方式，让模型持续学会相关能力。

背后有几项评价条件：

| 条件 | 含义 |
|---|---|
| 性能必须有增量 | 模型确实能够完成任务，performance 有提升；如果没有增量，就说明什么都没学到 |
| 原有通用能力大致不受影响 | 报告用一个约等号表示，原有能力应当不受太大影响，避免学了新知识却遗忘旧能力，不能“捡了芝麻丢了西瓜” |
| 能够可持续、多轮地学习 | 上下文进入参数，再有新的上下文继续沉淀到参数，再有上下文再沉淀，通过不断学习让智能体持续学习下去 |

报告指出，这与持续学习领域高度相关。参数化记忆与上下文蒸馏的目标非常接近，但两者有区别：上下文蒸馏本质上是“老师教学生”；参数化记忆是让一个智能体或 AI 把从上下文、环境中获得的知识真正沉淀到参数中，因此“老师”可以很多，环境可以是老师，其他智能体也可以是老师。它与知识编辑、遗忘、online learning、steering 等方向也高度相关，很多时候会有很强的交集。

### 核心设计难题

真正要做参数化记忆，报告提出几个核心问题。

第一，上下文中信息很多，找到关键信息还不够。模型拿到信息后要能学会这个知识点，还要能把相关知识点融会贯通。报告再次用洗衣机举例：学会一台洗衣机后，换一台型号类似的洗衣机，能否不看说明书、稍微摸索两下就学会使用？以前很多做法把上下文内容学进去后，模型往往只能拟合到这一类任务，融会贯通能力有局限。

第二，知识到底沉淀到参数的哪里。之前一些工作会设计专门的 attention block、memory block，或通过额外机制进行沉淀。模型架构本身很复杂，不同架构往往需要设计不同机制。

第三，怎样设计一套参数化机制，才能把信息真正学好。这是报告所述工作要探索的核心设计问题。Locus、Delta Memory、超网络等路线展示了不同切入方式，也暴露出各自的限制：可插拔记忆块要处理遗忘与泛化，超网络生成参数则面临训练难度和大量调参。因此，参数化记忆的难点不只是把上下文转成一组可训练参数，而是同时满足能力增量、通用能力保持、可持续多轮学习，并让新知识从具体经历上升为可迁移的经验。

## 参数化记忆的写入方法、规模化验证与边界

参数化记忆要解决的核心问题是：模型能否把上下文中的经验、事实或技能真正沉淀到参数里，使得上下文被移除后，这些信息仍然可用。报告给出的路线不是直接拿上下文做微调，而是先从人类处理经验的方式中找启发，再设计“先扩增、后写入”的机制，并在较大模型和多种任务上验证，最后讨论这条路线当前卡在哪里。从通用原理看，参数化记忆与检索式外部记忆相对：前者把信息固化在权重中，后者把信息留在上下文或外部库中；报告关注的正是前者的写入、保留与擦除问题。

### 从“脑补”开始：先扩增上下文，再考虑写入

报告用小孩子操作洗衣机的例子说明人类经验的使用方式：拿到一台新洗衣机时，人会先预想“按下某个按钮后机器会怎样动”，操作一两次后，已有经验又能帮助推演未来用途。这带有反事实推演和设想的意味。对应到模型，就是给定一段上下文和相关问题，让模型自己推演出未来可能有用途的指令、上下文或记忆内容。本质上，这是一种自动化的上下文扩增：让 AI 先“脑补”一些情况，再考虑未来可能怎么用。

这种扩增可以服务单个写入、多个写入，也可以服务持续写入。也就是说，写入参数之前，先让模型基于已有上下文生成更丰富的、可能对未来有用的信息，而不是只把原始上下文原样压进参数。

### 两条写入路径：强化已有连接与新增通道

有了经过推演扩充的上下文后，下一步才是把信息真正沉淀到参数中。报告引用脑科学和 Transformer 的相关研究，把学习新知识概括为两类机制，并对应到模型参数写入上。

**一是强化已有连接。** 两个神经元经常一起参与某个问题，连接会变强；对应到 Transformer，就是更新、增强已有的投影。报告提到这部分是与字节合作的工作，尝试过小模型、大模型以及一百多 B 的模型，并且该方式原生支持 MoE 架构。它的关键特点是：不改变模型原有架构，而是在已有权重上增加额外权重来实现参数化记忆学习。

**二是新增通道。** 如果连接原本不存在，就新增一个非线性通道，转写中称为“飞行通道”，用它新增一条原本不存在的连接。这相当于给额外架构打一个补丁，同样不破坏已有架构。两类范式可以独立发挥作用：需要强化已有连接时用强化方式，需要新增通道时用新增通道方式。它们也可以集成到大规模 MoE 模型中。报告展示了 MoE 模型上的处理示意：不同 expert 通过不同机制处理，右侧相当于额外增加了一个参数化记忆模块。报告强调，这一做法与已有工作不同，受到生物机制启发。

### 参数怎么学：逐层对比蒸馏与移除上下文后的稳定性

参数具体怎么学出来，报告说学习方式也比较朴素，类似蒸馏：先给模型上下文让它输出答案，然后把上下文拿掉，再让它输出答案。训练时对模型逐层进行参数化对比蒸馏，每一层之间有相关 loss，并加入额外的 MICE loss；几乎逐层在 hidden states 和 logit 层面进行学习。转写中还提到 MICE loss 用来补偿移除上下文后表征尽量不发生变化。

整套方法的目标可以概括为：给上下文时模型能学会；把上下文拿掉后，模型已经通过参数化模块把知识沉淀下来，最终形成参数化持续学习的能力。这里的关键不只是“记住答案”，而是让模型在上下文消失后仍保持相应的表征和行为。

### 规模化验证：场景、基线、设定与结果

报告称为了做通用工作，进行了大规模验证，并感谢工业界支持。验证场景覆盖了多类需要“把经验写进模型”的任务：

| 验证场景 | 关注点 |
|---|---|
| 智能体经验学习 | 把智能体经验沉淀到参数 |
| 智能体持续学习 | 连续更新后能否累积经验 |
| 代码 API 持续更新 | API 和库的使用方式变化后能否自适应 |
| 人格/个性化更新 | 个性化场景中的参数化更新 |
| unlearning 遗忘 | 能否把知识或能力去掉 |
| 知识编辑 | 对事实性知识进行修改 |

实验使用已有大规模数据集，转写提到 Alpha World Top Bench、R W K U 等。主要设定包括 single 和 batch 更新：每次给一个样本看能力，或给一大批样本看能力；还包括持续学习：给一个样本、参数化沉淀后，再给第二个、继续沉淀，再给第三个、继续沉淀。批处理方面，报告提到可以一次写入 50 个事实。

基线包括超网络 hypernetwork、TTT、Locus、Delta Memory，以及知识编辑方法等；这些方法也可以做类似事情，因此做了详细对比。评测模型包括千问、GPT 的 20B 和 120B 模型，以及 Gemma 3 等。

结果方面，报告称该方式可以在保留通用能力的同时把知识沉淀下去；图示中每个点是一个方法结果，左上角是 Delta Memory，右侧是该方法的結果，在不同指标上可以达到最优。与 Hyper Network 对比时，可以每次只写一条事实，或一批写入 50 个事实，在很多情况下能够抗干扰地让模型沉淀相关知识。报告还对比了 Locus、Memet、AlphaEdit、Roam 等经典知识编辑方法，并称相对 TTT 和上下文蒸馏也取得一定优势。

报告也提到一些有趣但机理尚不清楚的现象：某种 structure 方式在学习新 API 时可能最优，而另一种方式在某些编辑知识上最优。为什么某些任务强化固有连接效果好，某些任务增加连接效果好，目前还缺乏深入的科学分析。批处理方面，不论 20B 还是 120B 模型，都可以做大范围更新；持续学习方面，可以一轮上下文后更新知识并累积到记忆里，再更新一轮、再累积，不断学习新的事实知识。

### 边界：遗忘困难、经验耦合与“短不等于易学”

报告专门讨论了参数化记忆的边界，其中最重要的是遗忘/unlearning。模型学习过程中不一定希望什么都学到，有时希望把某些知识或能力遗忘掉，尤其是学到不该学的能力时要扔掉。海外很多企业关心这件事，国内也有团队在做；但对参数化方法来说，这一直是瓶颈和壁垒——知识和能力一旦进入参数，再想彻底拿掉很困难。报告称目前这项工作也很难彻底擦除一些信息。与同行讨论时，有人认为如果真的要做擦除，很可能还需要在机理可解释性上有进一步突破。

智能体方面，报告给出一个有趣结论：以前的智能体无论做 RSI 还是持续学习，很多做法是把智能体相关经验沉淀下来，沉淀后变得更好；而他们发现把经验沉淀到参数以后，有些情况下效果可能更好。这个结论与一些工作一致：经验沉淀到参数后，可能与原有经验形成更好的耦合机制，甚至超过纯带 context 的原模型；但具体增益与个别任务有关。

还有一个比较反直觉的结论：不是上下文越短就越容易学，这与任务难度有关。报告举例：给一个人或 AI 一条从未见过的知识点，虽然很短，每个 token、每个字都能看懂，但连在一起什么意思看不懂；这时让它学，不一定学得好，也不一定巩固。大规模实验发现，相对容易或与已有知识有关联的内容，参数化记忆可能巩固得更好；很短但很难、或完全没见过的知识，本来就学不会。因此，同样写入参数，到底写什么内容、怎么改、后面怎么用，都会影响实际效果。

报告还给出不同任务所需上下文信息量不同的例子：API 学习展示需要五千多个 token；事实编辑八百多个 token；某类抑制任务可能五百多个 token。这说明不同任务巩固所需的信息量不一样，需要根据情况判断。

### 持续更新中的工程与科学问题

报告最后讨论了持续频繁更新是否会带来负面影响。测试发现，经过持续频繁更新后，模型仍能维持正常能力，对通用能力也没有太大影响。该工作仍比较初步，代码正在走开源流程，文章已经挂出，并有较长的技术报告。

团队复盘时认为几个问题较有趣。

第一，上下文究竟需要什么样的信息。给同一个上下文改变形式，学习效率会不一样；对不同模型给不同内容，表现也会不一样。这说明数据的载体以及监督信号能够决定学习效率：形式较好时可以学得非常高效，形式有问题时给再多数据也可能学不进去。讲者认为这是让模型持续学习的有效 trick，掌握好的学习形式载体有利于提升学习效率。

第二，模型到底应该更新在哪里。目前有很多做法，例如直接更新 FFN、FFN 加 attention，或一些传统固定任务中的 LoRA 做法。这里没有最优解法，但报告发现有些任务使用 FFN only，即纯粹 FFN only，其保留能力的效果更好。

第三，灾难性遗忘问题一直没有被解决，学着学着很可能损失一些通用能力。讲者举例，很多大模型“说人话”的能力有所下降，有时会讲代码黑话；自己在使用 CodeX Clock 时也发现它讲代码黑话，不再是人类正常对话的语言。这被视为灾难性遗忘现象：以前很好的流畅自然语言文本输出能力，随着时间推移，被对齐等学习方式慢慢丧失。这时需要考虑什么时候可以 replay、什么时候可以不用 replay、怎样真正保留能力。报告做了 replay 相关实验，发现有时有一定副作用，有时有增益，可能要根据任务来看；冻结参数也不能保证行为真的不发生太大变化。此外，MICE 类分析显示，这种方式的确能够更好地稳定模型学习新知识和保留旧知识的整个过程。

在 MoE 架构上也做了分析，当时用了共享式 MoE 版本，发现效果可能更加高效，这也是一个有趣现象。

最后一个分析是容量问题，即参数化记忆到底需要多大容量。讲者一直觉得这里可能存在类似 law 的东西，包括什么时候存在模型真正参数化的可学习区域，如何高效地把上下文形成类似 agent 的海马体，而模型参数类似 AI 的皮层；皮层中的某一环节可能是模型长期记忆、永久记忆的关键区域。这个区域的容量是什么、背后的机制是什么、到底能学习多少知识，都还不清楚。据讲者所知，人脑神经元个数与目前模型还有一定差距。如何把 AI 模型的皮层记忆能力、参数化记忆能力做得更好，甚至真正把上下文知识沉淀下来，背后肯定有科学原理和科学规律。当时做了一些比较初步的分析去探索，但规律不是很明显，技术报告里有一些相关思考。

整体来看，这条路线把“上下文推演扩增—参数写入—多场景验证”串了起来，展示了参数化记忆在智能体经验、API 更新、知识编辑等任务上的潜力；但边界同样清楚：写入可以做得比较有效，彻底擦除仍然困难，更新位置、数据载体、任务难度和容量规律都还没有统一答案。

## 个性化记忆：动机、构建流程与任务记忆的差异

### 从一个日常问题出发：为什么智能助手需要“记住用户”

报告用一个很直接的问题开场：同样是智能助手，用户第一次使用它，与使用半年之后，它对用户的理解应当有什么不同？如果一个大模型在被长期使用后，仍然不能理解用户希望回答更简洁，或者不知道用户偏好哪类内容，那么即使它能答题、能帮忙做事，也仍然称不上“懂”这个用户。这个落差正是个性化记忆要解决的问题——把长期积累的用户信息转化为能支撑个性化服务的记忆。

这里的“记忆机制”被定义为一个长期存在的组件，允许智能体在多个步骤、多个会话之间写入、更新和调度信息，并逐渐把经验记录下来，帮助日后做出更智能的回答。在智能体执行复杂任务时，它要规划、采取行动、调用工具，环境会给出反馈；记忆机制是连接这些环节的桥梁，把历史经验巩固、内化下来。

记忆机制的必要性可以归结为三点：

- **控制上下文增长**：不使用记忆，上下文窗口会不断变长；而即使窗口变长，模型也未必能充分利用全部输入，会出现 lost in middle 现象，忘掉中间部分的 context。因此需要用记忆对上下文做总结、summary 和简化。
- **支撑跨会话任务**：任务越来越长，很多任务要跨多轮对话、多个会话才能完成。用户常常开很多窗口，后一个窗口的内容依赖前一个窗口，这就是跨对话、跨域使用记忆的形态。
- **保持一致性并实现个性化**：有了记忆，智能体才能保持一致，提供个性化服务，并在使用中逐渐改进。

报告把记忆机制分为两大类：一类是融合在模型内部的**参数化记忆**；另一类是在外部构建知识库的**外部记忆/符号化记忆**。面向用户个性化建模的记忆大部分属于后者——调用时采用类似 RAG 的方式，从记忆库中检索相关内容，作为 context 放入上下文，从而做更好的个性化生成。

一个直观的例子是：记忆库中保存了用户“常买蓝色衣服”“看重性价比”“喜欢浅色的小配饰”等偏好。当用户问“想要一条适合毕业的裙子”时，智能体检索记忆，推断出用户可能喜欢蓝色裙子并据此推荐，随后再推荐白色配饰，以满足个性化需求。

这类机制已在多个产品中落地。ChatGPT 在 2024 年发布记忆机制：用户在一次对话中说明自己养了一只金毛巡回犬和一只缅因猫，ChatGPT 以文本形式记录；用户另开一个对话要求“画我的宠物冲浪”，模型检索出这两只宠物并放入上下文，生成符合宠物形象的图片。记忆可以从以前的对话、memory 的演化、library，或用户连接的 email 等内容中提取生成。Kimi 在用户说“我通常用 C++ 编程”时会做 memory update 写入记忆库；Claude 也会根据以往对话对记忆做总结。

### 一个简单的外挂记忆构建流程：记录、总结、检索、更新与遗忘

报告引用了一篇 2024 年较早、较经典的外挂记忆机制工作，说明如何构建一个简单的个性化记忆系统。系统分为两块：左侧是外挂的记忆系统，右侧是用户与大模型日常交互的界面。

记忆记录的内容主要有三类：

1. **用户历史对话**：记录每轮对话发生的时间与具体内容，并按天对对话做事件 summary，记录用户当天做了什么事情；
2. **用户偏好或倾向的每日总结**：例如总结出用户可能比较开朗、对外界有好奇心；
3. **可检索的记忆库**：调用记忆时对库中内容进行检索。

与传统 RAG 的关键区别在于，这套机制会做**迭代的 update 与遗忘**。传统 RAG 不强调更新和内化，而记忆机制必须处理这两件事，这是它保留经验的重要过程。该工作的做法比较探索性、也比较简单：借助艾宾浩斯遗忘曲线按时间衰减——长期未被使用的记忆权重不断降低，经常被检索、被用到的记忆强度则增加。

由此可以看出，记忆机制记住的不只是任务事实。在个性化场景中，它还要记住**这个人是谁、他喜欢什么、他正在发生怎样的变化**。

### 当输入从对话变成行为：隐式偏好带来的建模困难

上述 ChatGPT 和这篇论文的记忆机制，输入多是文本对话。但还有一大类场景，输入是潜在的用户行为，例如推荐系统。用户的历史记录往往没有明确真值，只有隐式行为：某用户看过《寄生虫》《瞬息全宇宙》《灵亚之旅》等电影，APP 要预测他未来可能看什么。对这类数据做兴趣建模、记忆建模，困难明显更多。

- **行为是隐式的，没有直接真值**。文本对话可以较容易地 summarize 出偏好，而隐式行为中的偏好潜在蕴含在行为里，无法直接监督记忆的构建。
- **偏好信号离散、稀疏且带噪声**。用户可能只看过两部犯罪悬疑片，行为在时间上间隔分布、数量稀疏；其中还可能混入偶然行为，例如《芭比》是陪女朋友看或误点开的，并不代表真实偏好。
- **偏好是多面的**。同一用户可能同时有悬疑、科幻、温情动画等多条兴趣线，把这些行为合成“喜欢看电影”这样的笼统标签并不合适，机制上需要同时建模多条兴趣线。
- **偏好是动态的**。用户偏好实时变化，需要靠记忆机制去捕捉。

### 用户建模记忆与对话/任务记忆的四点差异

在上述分析基础上，报告把用户个性化建模中的记忆与常见的对话/任务记忆做了四点对比：

| 维度 | 对话/任务记忆 | 用户建模记忆 |
| --- | --- | --- |
| 信息来源 | 用户明确说出的文本 | 除显式对话外，还包括点击、购买、评分等隐式行为记录 |
| 记忆内容 | 事实、事件、上下文 | 更强调行为背后的潜在用户偏好 |
| 验证方式 | 多有标准答案，benchmark 会标出 ground truth、应调用哪些记忆 | 偏好没有真值，只能靠下一次行为间接验证记忆是否捕捉正确 |
| 最终用途 | 回答问题、保持对话一致性 | 推荐任务、模拟用户、生成符合个人风格的内容 |

这四点差异决定了该领域的核心难点：**如何从隐式行为中构建记忆，以及如何在需要时用对记忆**。报告据此把后续讨论分为“记忆构建”和“记忆使用”两部分——构建包括面向影视行为场景搭建符号化记忆库、做记忆更新等；使用包括跨域使用，以及在无真值、无 ground truth 的场景下做好记忆检索。

## 记忆的组织形式与用户行为记忆的构建路线

报告先讨论了一个基础问题：记忆在系统中究竟以什么形式存放，随后把问题落到用户行为数据上——面对隐式、离散、稀疏、多面和动态的行为，应该如何构建可用的用户记忆。前者是“记忆如何组织”，后者是“记忆如何从行为中生成并演化”。

### 一、三类常见组织形式：从独立条目到关系结构，再到多粒度层次

报告引用记忆领域的经典梳理，将常见组织形式概括为三类。

**第一类是扁平式记忆。** 记忆被当作一组独立条目或按顺序存放，不额外建立条目之间的显式关系。它的内容可以很不一样：既可以是经验总结，例如从对话中总结出“写代码前先核对版本要求，避免盲目重复安装”；也可以是切分好的文本块、一轮轮对话，或对每轮对话、文本块调用大模型生成的 summary。MemoryBank 这类做法存储多轮对话，就是报告举出的例子。扁平结构的优点是简单直接，检索时主要依赖条目本身，但记忆之间的关系没有被显式表达出来。

**第二类是结构化记忆。** 在条目之外增加边、图或树，把记忆之间的关联表示出来。这样检索到某个节点时，可以把与它相关的记忆一起作为上下文送给大模型，而不是只取单条记忆。报告提到，图结构可以存成 graph，例如 i-memory 一类做法；节点可以承载不同类型的内容，包括图片、chart 等。若记忆之间存在父子关系，也可以组织成树。结构化记忆的价值在于：检索不只命中一个点，还能顺着关系把一组相关记忆带出来。

**第三类是层次化记忆。** 报告中分为金字塔型和多层型。金字塔型如 G-memory、CI M 等工作，底层保留较细的细节，越往上做力度越大的总结，形成从细节到摘要的多粒度表示。多层型同样让不同粒度的内容共存，例如原始文档/原始文本与由原始文本生成的 QA 对可以分层存放。这样做的目的是在不同抽象层级上保存信息：既保留可追溯的细节，也能在上层快速获得概括性内容。

### 二、用户行为记忆的核心难点与三条构建路线

把上述组织形式放到用户行为场景中，问题就变成：用户行为往往是隐式的，只有点击、购买等信号；行为数据又是离散、稀疏、多面和动态变化的。因此，核心不是简单“存一段用户画像”，而是如何用行为数据构建可更新、可检索、能反映多个兴趣侧面的记忆。报告给出了三条有代表性的路线。

**路线一：把物品记忆迁移到用户记忆。** 报告介绍了一项发表在 WWW 2024 的智能体加推荐系统工作。由于用户通常没有足够的显式偏好文本，方法从用户交互过的物品中提取知识，再迁移到用户身上。系统建模两类记忆：用户记忆描述用户偏好，物品记忆描述物品特征。举例来说，初始用户记忆可能是“喜欢电子摇滚乐”，而用户交互过的物品可能对应流行音乐、原声音乐等。系统回放用户历史记录，用物品记忆更新用户记忆；用户每交互一个物品，就用真实选择与模型预测反馈不断迭代，改写用户记忆和物品记忆，把真实交互过的物品记忆逐步迭代到用户身上。

这条路线的一个重要作用是缓解用户行为数据的隐私挑战：用户侧不必依赖大量显式偏好文本，知识可以从交互过的物品侧提取并迁移。不过报告也指出，它主要是在物品记忆和用户记忆之间做迭代，没有显式表示用户与物品之间的协同交互关系。

**路线二：把用户—物品交互建成图，显式利用协同信号。** 推荐系统中非常重要的一类信号是协同过滤信号：相似用户的选择可以帮助推断当前用户的偏好。Memrec 把“所有用户与所有商品的交互记录”建模成一张图，形成二维结构化表示。做记忆检索时，可以从当前用户的兴趣出发，找到相似用户的其他兴趣，再把这些协同记忆附加到当前用户身上。方法显式聚合邻居信息，增强协同信息建模。

这条路线的直接收益是解决单个用户行为稀疏的问题：当一个用户自己的记录很少时，图上的邻居关系可以提供额外信息。报告者还提到自己使用过该方法，效果很好。与路线一相比，它补上了用户—物品之间的协同关系，而不只是把物品特征迁移给用户。

**路线三：把用户偏好组织成细粒度原子记忆。** 这是报告者团队的工作。其出发点是：此前一些方法为每个用户保存一整段记忆，并整段 overwrite/改写；当用户兴趣更新时，旧记忆容易被覆盖，很多信息会丢失。但用户有些基本记忆并不会忘记，兴趣本身也具有多面性。

因此，该方法把用户表示成多个兴趣原子，例如 M1 表示“喜欢描述家庭生活的电影”，M2 表示“喜欢冒险性电影”。这样就把粗粒度用户记忆变成细粒度、结构化的记忆，并支持动态演化和实时更新。

其流程大致分为三步：

1. **记忆构建。** 把原始交互中的偏好表示成原子化记忆单元，并逐步形成记忆社区。构建社区时使用两跳广度优先搜索，找出与某个原子记忆相似的两跳原子记忆，放在一起构成 prototype/记忆社区。
2. **动态更新。** 新交互到来时，如果有相似记忆就合并；如果没有相似记忆，就形成新的记忆。这样既保留旧的基本偏好，也能容纳新兴趣。
3. **记忆检索。** 支持从局部到全局的检索。一个 query 到来时，先检索用户对应的原子记忆，再通过该原子记忆所在社区，快速检索到其他用户的相似记忆。这样既能检索个人偏好，也能获得社区层面的协同知识，用共享知识补充个人记忆。

报告中给出的社区示例包含多条相似原子记忆，例如喜欢家庭电影、喜欢温馨轻松的人物成长故事等。实验结果表明，细粒度、结构化的用户记忆建模可以显著提升推荐系统性能。

### 三、三条路线的关系与各自侧重

| 路线 | 记忆结构 | 主要针对的问题 | 报告中的关键差异 |
|---|---|---|---|
| 物品记忆迁移到用户记忆 | 用户记忆与物品记忆，回放历史并迭代改写 | 用户缺少显式偏好文本；缓解隐私挑战 | 能迁移物品知识，但没有显式表示用户—物品协同关系 |
| 用户—物品交互图 | 用户—物品图，显式邻居关系 | 协同过滤信号；单用户行为稀疏 | 通过图上的相似用户传导偏好，显式聚合邻居信息 |
| 细粒度原子记忆与社区 | 原子记忆、记忆社区，局部到全局检索 | 整段覆盖导致信息丢失；兴趣多面、动态演化 | 把粗粒度记忆拆成原子，并通过社区共享知识 |

从报告的分类看，三类组织形式与三条构建路线并不是一一绑定的。扁平、结构化、层次化回答的是“记忆以什么形态存放”；物品记忆迁移、交互图、原子记忆与社区回答的是“如何从用户行为中构建和演化记忆”。路线一更接近以条目形式保存用户和物品记忆；路线二明确采用图结构；路线三则把细粒度原子记忆进一步组织成社区，并在检索时从个人原子走向社区共享知识。

三条路线也体现了问题重心的递进：先解决用户没有足够显式偏好文本的问题，再解决单个用户行为稀疏、协同信息不足的问题，最后处理整段记忆覆盖造成的信息丢失，以及用户兴趣多面、动态变化的问题。报告最后把落点放在“如何通过用户行为数据构建记忆”这一核心问题上，而细粒度、结构化、可演化的组织方式，是其中一条较完整的实现路线。

## 跨域记忆迁移与两阶段强化学习

### 问题起点：目标域历史不足时，能否借用源域记忆

讲者从“记忆如何构建”转向“记忆如何使用”，重点讨论个性化记忆中的跨域使用问题。典型场景是目标域历史严重不足：用户新开一个 chat，或刚开始使用一个新 app，目标域内可观察到的行为很少，直接做推荐或个性化生成会比较困难。此时可以利用用户在源域积累的记忆，为目标域补充信息。

报告中的例子是图书域到电影域的迁移：用户在图书域有大量购买经验，表现出喜欢太空探索类图书，也喜欢精装版、大字号图书；但他在电影域交互很少。系统可以把图书域中“喜欢太空探索、硬科幻”这类偏好迁移到电影推荐中，结合当前需求改善推荐效果。关键点在于，并非所有源域偏好都适合迁移。“喜欢太空探索、硬科幻”与电影内容偏好相关，可以迁移；“喜欢精装书、大字号”属于装帧或阅读载体偏好，未必能说明电影偏好，因此不应被检索进目标域上下文。

| 源域中观察到的偏好 | 是否适合迁移到电影推荐 | 原因 |
|---|---|---|
| 喜欢太空探索、硬科幻 | 适合 | 与内容主题相关，可辅助电影选择 |
| 喜欢精装版、大字号图书 | 不适合 | 属于装帧/载体偏好，与电影内容关联弱 |

因此，跨域记忆迁移的核心不是“把源域所有偏好都搬过去”，而是“选择性地使用源域记忆”。

### 核心挑战：选择性检索与可学习偏好

讲者将挑战概括为两方面。

第一，需要**选择性的检索机制**。源域记忆里既有可迁移的内容偏好，也有只适用于源域的载体偏好、场景偏好。如果全部检索进目标域，不仅无益，还可能干扰推荐。系统必须甄别哪些记忆对当前目标域任务有用。

第二，需要**可学习的训练偏好**。现实中缺少直接监督信号告诉系统“源域中的哪条知识应该迁移”。系统需要决定检索哪些内容，还要刻画检索质量如何影响后续推荐性能。换句话说，不仅要会检索，还要学会“为下游任务检索”。

为了解决监督信号不足，讲者提到使用教师模型进行标注：用 GPT 等闭源大模型对相关偏好片段进行标注，为检索提供较弱的监督信号，并据此构造训练数据。

### 方法：先把源域建成记忆，再训练“检索—推荐”两阶段行为

讲者提出的方法名为 **Retrievers for Memory Transfer to Recommend**。方法首先把源域信息建模成记忆机制。例如在图书域，把用户信息组织成记忆知识库：用户喜欢算法相关书籍，喜欢阿加莎·克里斯蒂的推理小说等。到了目标域推荐时，assistant 从用户记忆中做选择性检索，选出适合的 memory，辅助目标域后续推荐。

训练分为两个阶段。

**第一阶段：指令微调，建立基础检索与迁移能力。** 这一阶段让模型具备基本的 retrieval 和 transfer 能力，即能够从源域记忆中找出相关内容，并将其用于目标域任务。

**第二阶段：解耦的两阶段交互强化学习。** 讲者提出“解耦的两阶段交互”强化学习方法，把检索奖励和推荐奖励结合起来。这里的“两阶段”对应同一 policy 的两轮对话：模型先执行记忆检索，再基于检索结果完成推荐。两轮使用同一个模型策略，而不是两个独立模型。

奖励设计上：

- **第一阶段奖励**关注模型能否检索出正确的记忆，并对错误检索进行惩罚；
- **第二阶段奖励**利用最终推荐的真值 ground truth，根据下游推荐效果设计奖励；
- 同时，利用教师模型标注构建中间阶段的监督信号；
- 最终对整个 policy 进行联合优化。

作为背景，强化学习在这里的作用不是让模型“自由发挥”，而是用奖励塑造两轮行为：第一轮学会选对记忆，第二轮学会把选出的记忆转化为更好的推荐。两阶段奖励解耦，使检索质量和最终推荐效果都能进入优化目标。

### 例子与结果

报告给出了跨域推荐任务上的案例。用户此前看了两部电影，模型从源域检索出两条 memory，辅助推荐出《憨豆先生的假期》。当用户的交互记录不同，模型会有选择地从不同源域的记忆中检索——材料以黄色、蓝色源域作区分——进而推荐出新的电影。这说明模型并非固定搬运全部源域信息，而是会随用户当前交互选择不同的记忆片段。

在多个跨域推荐任务上，该方法相比传统跨域推荐方法、基于大语言模型的推荐方法等有大幅提升。报告据此说明：把记忆机制用于用户建模，并通过跨域检索补充目标域信息，可以显著提升跨域推荐效果。

### 边界与限制

从报告材料看，这一方法的关键优势在于把“选择性迁移”变成了可训练行为：用教师模型提供弱监督标注，用两阶段强化学习分别约束检索和推荐。但它也带来几个需要关注的问题。首先，监督信号部分依赖教师模型的弱监督标注，标注质量和覆盖范围会影响模型学到的迁移偏好。其次，跨域迁移存在负迁移边界：哪些偏好可迁移、哪些不可迁移，既需要学习，也需要对任务相关性有判断。最后，报告给出了多个任务上的整体提升和 case study，但材料未展开具体数据集、指标数值和消融结果，因此各模块的定量贡献、更多领域上的泛化表现，以及真实产品环境中的稳定性，仍需进一步验证。

## 记忆检索：从“相似”转向“有用”

个性化记忆系统长期积累大量用户记忆后，真正困难的问题不是“能不能检索到”，而是“检索到的记忆是否值得放进上下文”。报告把这一问题概括为：给定当前 query，如何从海量用户记忆中选出真正能提升当前任务表现的记忆。现有做法通常把 memory 和 query 都编码成 embedding，按语义相关性选取 top k 条记忆，再拼入 prompt。报告指出，这条链路隐含了一个未经检验的假设——语义越相关，记忆越有用。实际并非如此。

### 相关性检索的失效：一封拒绝会议邀请的邮件

报告给出的例子很直接。当前 query 是“帮我写一封拒绝会议邀请的邮件”。相关性检索可能返回两类记忆：“上次会议在上海”“会议通常在周二上午”。它们都提到了会议，与 query 在语义上高度相关，却不能帮助模型完成当前任务。用户真正需要的是如何表达拒绝、以什么理由拒绝、用何种语气拒绝，而会议地点和惯常时间并不提供这些信息。换句话说，这些记忆只共享了话题，没有提供任务所需的行为依据。

围绕这一现象，报告总结了三个发现或难点。

第一，**相似不等于有用**。语义上最相似的历史未必能提升最终生成质量。报告中展示的实验把检索记忆的语义相关性作为横轴、加入该记忆后的任务 performance 作为纵轴，发现不少高相关记忆加入后，任务表现甚至低于不加记忆的 query-only 基线，部分高相关记忆会导致任务 performance 降低。这说明相关性分数与生成收益之间并不存在稳定的一致性。

第二，**组合效用不可加**。常见做法是把 top k 条记忆一起放入上下文，但单独看有用的几条记忆，组合后可能冗余，甚至互相冲突。集合的效用不等于各条记忆效用的简单相加。这使“逐条打分再取前 k”的检索范式面临一个结构性限制：即使每条记忆单独相关，拼在一起也未必构成一组好的证据。

第三，**选择过程没有反馈**。以往由外部检索器按相似度决定使用哪些历史，这一过程不可学习，也得不到最终生成质量的监督。模型无从知道哪些偏好对当前 query 真正重要，更无法从生成结果反推检索选择是否合适。

### 效用驱动的检索：Utility Gain 与 Identify-then-Generate

针对上述问题，报告提出让大模型学会检索真正有用的记忆，再基于这些记忆做个性化生成。核心机制被称为 **Utility Gen（效用增益）**：对一个 query 先检索并组合 memory，计算加入 memory 后的任务 performance，再减去不加 memory 的 performance，用这个增益作为使用该记忆的 reward。可以简写为：

```text
utility gain = performance(query + memory) − performance(query)
```

如果在线计算这一增益，需要多次 rollout，速度很慢；因此作者离线计算一张表，记录 query 加上不同记忆组合后的效用。表只需计算一次并保存，后续强化学习把它作为中间过程奖励，查询效率为 O(1)。这实际上把“这条记忆有没有用”的评估从在线检索阶段前置到了离线效用计算阶段。

方法名为 **Identify then Generate**，训练采用两步马尔可夫决策过程，两个阶段共享同一个策略、同一个模型。

| 阶段 | 目标 | 输出与奖励 |
|---|---|---|
| 第一阶段：离线冷启动 | 学会识别要检索哪些 memory | 只输出检索出的 memory 索引，不生成后续回复；奖励直接来自预先算好的 utility gain 表，通过 GRPO 把梯度回传到识别 token |
| 第二阶段：在线联合优化 | 学会如何使用记忆进行生成 | 在已具备记忆识别能力的基础上，联合优化检索与生成过程 |

第一阶段的关键在于让模型学到“哪类偏好对哪类 query 有用”，而不是只学“哪条记忆与 query 长得像”。第二阶段再让模型学会把选出的记忆用于生成。报告称，该方法在个性化文本生成的 LAMP Benchmark 六个任务上均达到 SOTA，各评价指标上效果显著，并对比了启发式检索、微调式以及基于 RL 的方法。报告由此得出的判断是：基于强化学习、基于学习的方法可以为中间过程提供 reward，帮助模型学会检索哪些记忆来辅助更好的生成。

### 互补路径：相似度检索加层级记忆图全局检索

报告还提到另一项近期工作，同样发现仅通过相似度检索效果可能不好。该工作设置了两条互补的检索路径：第一条直接做相似度检索；第二条做全局检索，把整个记忆组织成一个 hierarchical 图，检索时通过 global search 在语义层级图上自上而下进行。最后把相似度检索结果与全局检索结果进行组合，形成更完整的相关证据来辅助生成。

这条路径与效用驱动并不矛盾，而是提供了另一种补足相关性检索的方式。相似度检索擅长抓住与 query 表面语义接近的局部记忆；层级图上的全局检索则可以在更高语义层缩小范围，再向下寻找证据，减少只盯着局部相似片段而遗漏整体上下文的问题。两者组合后，目标不是简单扩大 top k，而是让进入生成上下文的证据更完整。

### 世界知识缺口：猫、百合花与“养猫”记忆

问答环节把一个更深层的问题提了出来：记忆检索不只是“从记忆库中找相似条目”，还可能涉及世界知识推理。提问者提到 In Mind 数据集在 query 与记忆之间建立了世界知识连接。例子是：用户的记忆是“养了一只猫”，当前活动是选择花卉；世界知识是猫对百合花有毒或过敏。若记忆系统要依据用户背景帮助选花，智能体很难仅凭“养猫”这条记忆与“选花”之间的语义相似性，避免推荐百合花。

这里的困难有两层。第一层是检索关联：在当前 query 的语义邻域里，“养猫”与“选花”并不接近，仅靠 embedding 相似度可能不会把这条记忆召回。第二层是推理关联：即使召回了“养猫”，系统还需要借助“猫—百合花—有毒”的世界知识，才能把它转化为“不要推荐百合花”的决策依据。提问者因此把问题概括为外部检索或世界知识推理问题，而不只是记忆检索问题：如何把世界知识与用户记忆关联起来，并在检索时适时把相关记忆与当前问题结合。

提问者考虑把记忆参数化，利用大模型内生的世界知识做世界知识增强的检索，但缺少可靠思路。回答建议参考参数化记忆与非参数化记忆结合的工作，例如转写中提到的 MemT，把两类知识结合起来做更好的检索生成。作为背景，参数化记忆可以理解为模型权重中隐含的知识，非参数化记忆则是外部可检索、可更新的存储；两者结合的方向，是让模型既利用外部用户记忆，又调用内生世界知识完成关联。回答者判断这是一个很好的前沿方向，因为记忆可能不止一种形式，需要多种知识结合，包括参数化记忆与非参数化记忆的结合，才能获得更好的生成效果。

从这场讨论看，记忆检索的难点已经从“排序函数是否更准”推进到两个更基本的问题：一条记忆是否对当前生成有增益，以及一组记忆能否与当前任务和必要的世界知识共同构成有效证据。前者要求从相似度驱动转向效用驱动，后者则要求检索系统具备跨语义邻域连接知识的能力。两条线索都还没有被完全解决，但已经清楚指出了相关性检索单独使用时的边界。

## 个性化记忆生命周期、产品化与未来方向

报告最后把用户个性化建模中的记忆问题收束到“智能体记忆生命周期”上：一方面讨论如何从用户行为中构建记忆、如何在任务中使用记忆；另一方面按记忆准入、写入、演化、检索四个阶段梳理近期研究，并进一步讨论记忆系统产品化之后的需求与未来方向。这里的重点已经不只是“给模型加一个记忆库”，而是让记忆成为持续理解用户、支撑跨场景任务的基础设施。

### 从隐式行为到可用记忆：构建与使用的难点

个性化记忆构建的第一个难点，是如何从隐式用户行为中形成记忆。用户不会总是显式告诉系统“我喜欢什么、我习惯什么”，更多信息散落在行为序列里。报告梳理了一条演进路线：早期工作让“物品记忆”辅助“用户记忆”，即通过用户接触过的物品来间接刻画用户；之后出现二维图形式的记忆，以及层次化（hierarchy）记忆，用更复杂的组织结构把分散行为组织成可用的用户记忆。这条路线背后的共同问题是：如何把低层、碎片化的行为信号转化为高层、可调用的个性化记忆。

第二个难点是记忆构建的效率。随着对话和历史信息变长，系统不可能把所有原始内容都保留下来。报告提到，目前不少 SOTA 工作从“记忆准入”或“记忆分类”的角度提升记忆构建与使用效率。也就是说，在记忆形成之前先判断哪些信息值得进入记忆、哪些属于冗余，或者先对记忆进行分类，以降低后续构建和调用的成本。

在记忆使用阶段，报告特别提到跨域记忆使用，并指出了一个重要限制：单纯基于相似度的检索效果可能并不好。相似度只能判断文本表面是否接近，但个性化任务真正需要的是“这条历史信息对当前任务是否有用”。因此，如何设计更好的记忆检索方法，成为记忆使用阶段的核心问题之一。这个问题也贯穿了后面生命周期中的检索研究。

### 按生命周期看四个阶段：准入、写入、演化与检索

报告按智能体记忆生命周期总结了非参数化记忆领域的研究方向。作为背景，这里的非参数化记忆可以理解为把记忆放在模型参数之外的外部存储中，通过写入、检索和组织参与推理，而不是只依赖模型参数内化知识。报告关注的正是这类外部记忆如何被构建、维护和使用。

| 阶段 | 核心问题 | 报告提到的主要方向 |
|---|---|---|
| 记忆准入 | 哪些原始信息值得进入记忆 | 过滤对话冗余；识别恶意注入，避免形成有害长期记忆 |
| 记忆写入 | 记忆如何形成、如何组织 | 把记忆操作视为可学习决策，用下游任务反馈改进写入；用超图等复杂结构组织记忆 |
| 记忆演化 | 记忆出错后如何发现和修正 | 追溯记忆贡献、判断错误来自准入还是写入，进而迭代整体记忆系统 |
| 记忆检索 | 当前任务该调用哪些记忆 | 召回重排、检索后改写、检索时推理、用目标与证据缺口指导检索 |

在记忆准入阶段，一个直接目标是过滤原始对话中的冗余信息，做高效的记忆构建。但准入不只是效率问题，也涉及安全性。报告提到，有工作构建 Benchmark 研究如何识别恶意注入，避免大模型把恶意注入转化为长期记忆，进而危害后续使用。这说明记忆准入实际上是长期记忆的安全边界：什么能进入记忆，决定了系统未来会被什么信息影响。

在记忆写入阶段，报告概括了两个前沿方向。第一个方向是把记忆操作视为可学习的决策，并用下游任务反馈改进记忆写入策略，例如 memory agent、memory T、fine memory 等工作设计强化学习 reward 来帮助模型更好地写入记忆。这里报告人特别说明了一个区别：报告人自己的工作是用下游任务反馈帮助记忆检索，而这些工作是用下游任务反馈帮助记忆写入。两者都利用下游反馈，但作用环节不同。第二个方向是设计更复杂的记忆结构，例如用超图等结构更好地组织记忆。

在记忆演化阶段，较 SOTA 的工作关注追溯记忆的贡献、判断记忆中存在哪些错误。材料中提到的 MemQ、MemTrace、StreamMem 等（名称按转写）会通过最终结果追溯问题出在记忆准入阶段还是记忆写入阶段，从而帮助迭代整体记忆系统；也有工作从不同层面关注记忆演化。这里的思路不是把记忆当作一次性写好的静态库，而是把错误定位和系统迭代纳入生命周期。

在记忆检索阶段，报告归纳了四类工作：第一类是在召回阶段训练模型做记忆重排，并发现用任务结果训练重排模型后，后续任务效果更好；第二类是检索后对记忆做组织改写；第三类是检索时做推理；第四类是用目标和证据缺口指导记忆做更好的检索。这四类工作分别从排序、组织、推理和检索目标几个角度，回应了“相似度检索不够好”的问题。

### 产品化：从一次问答到持续服务

报告把记忆系统的影响概括为推动 AI 从单次问答走向持续性服务。最初的 AI 可能只能回答一次问题，例如推荐从北京到上海的出行方式；后来记忆系统让 AI 能理解同一个用户，并持续推进跨场景任务，使个性化从“一次回答中的适配”延伸为“长期协作中的连续性改进”。这也是个性化记忆产品化的根本动机：用户需要的不是每次重新介绍自己，而是系统能够积累并正确调用历史信息。

产品层面，GPT、Claude、Gemini 等已经出现个性化的智能体系统；材料还提到今年年初一款产品中记忆机制占其功能的很大一部分（产品名转写不清）。九月至十月前后，Meta 等也推出 Personal Agent 类应用产品，使用了很多记忆功能；记忆张量推出 MT 原生记忆基础模型。报告认为，主流产品正在把记忆系统带入日常使用。

这些产品形态背后有共同需求：知道用户是谁、知道用户正在做什么，以及知道哪些历史信息对此刻是有用的。前两点对应用户建模和任务状态理解，第三点对应记忆检索的效用判断。产品化因此不是简单增加记忆容量，而是要让记忆在具体时刻可被正确调用。

### 未来方向：自我递归改进与持续循环

报告收尾时把未来研究指向记忆系统自身的学习与自我递归改进。现有系统已经能够通过记忆机制迭代，以“内化”的方式持续更新记忆内容、进行持续学习。更重要的方向是让长期记忆不仅保存过去，还能支撑整个记忆系统的持续循环，使记忆学习机制变得更好。

从生命周期看，这意味着准入、写入、演化和检索不应是彼此割裂的流水线。准入决定什么能进入长期记忆，写入决定记忆如何形成，演化负责发现和纠正错误，检索决定此刻调用什么；而下游任务反馈、错误追溯和检索效果又可以反过来改进这些环节。报告给出的方向不是单点地扩大记忆，而是让记忆系统在持续服务用户的过程中形成自我改进的循环。

## 多模态记忆：动机、总体框架与多模态对话记忆

### 为什么记忆需要多模态

多模态记忆的必要性首先来自感知本身。人和动物理解世界并不只依赖文本，图像、声音、视频等都是重要信息来源。如果先把图片转成文字描述，再只记忆其中的“关键信息”，就会产生记忆损失：一些视觉细节、空间关系、声音线索以及图文之间的对应关系，可能在转写过程中被丢掉。

当前不少智能体记忆系统仍是文本模态的，例如报告提到的 Memling、LongM、MemOS，主要面向文本对话记忆，或智能体完成任务过程中的轨迹文本记忆。但真实应用并不总是文本输入：

- 手机、车载智能助手、AI 眼镜接收的是第一人称的视觉与文本感知；
- 具身智能需要理解连续的环境观察；
- GUI agent 的输入常常是一串视频、图片或操作轨迹。

因此，仅用文本承载历史信息不足以支撑这些场景。多模态记忆要解决的是：智能体如何从包含文本、图片、声音、视频的历史中提取、保存并调用经验。

### 总体框架：从交互历史到记忆增强

报告给出的总体框架可以概括为一条链路：

1. 智能体与环境进行多轮交互；
2. 交互历史中包含文本、图片、声音、视频等多模态信息；
3. 从历史中提取记忆；
4. 用记忆增强多模态智能体，提升当前任务能力，同时保留历史经验。

在记忆形式上，框架区分了两类路径：

- **参数化记忆**：把历史信息直接训练到模型参数中；
- **外部记忆系统**：把记忆存放在模型之外，通常包括记忆写入、记忆管理和记忆检索三个环节，再利用检索结果增强智能体。

这一划分与文本记忆系统的基本结构相似，但多模态场景下的写入、管理和检索都更复杂：系统不仅要处理文字，还要建立图像、声音、视频与文本之间的关联。

从发展脉络看，2021 到 2023 年主要是轨迹记忆的初步方法，当时较多依赖 GPT-4V、GPT-4o 等闭源多模态模型的能力。此后，开源和闭源多模态模型能力逐步增强，报告中提到千问系列后续版本、GLM-V 等模型，多模态记忆工作也随之增多。

### 四类典型场景

报告将多模态记忆场景大致分为四类：

| 场景 | 输入特点 | 说明 |
|---|---|---|
| 多模态对话记忆 | 图文交错的长对话 | 记忆对话中出现的事实、实体和图文关系 |
| 多模态文档记忆 | 长文档中的长文本与图片 | 需要同时理解文档文字和其中的图像信息 |
| 长视频记忆 | 较长的视频流 | 从连续视频中提取和调用历史信息 |
| 智能体多模态轨迹记忆 | 视频、图片、操作轨迹等 | 面向具身智能、GUI agent 等任务过程 |

每一类场景都有相应的测试集。多模态长对话中较有代表性的是 Locomo，用于测试较长图文对话中的记忆问题。

### 多模态对话记忆：Locomo 与 Memor words

多模态对话记忆的典型数据形式是两个人的图文交错对话。以 Locomo 为例，对话历史较长，并围绕对话内容设置记忆相关问题，用来检验方法能否从历史对话中找回并利用信息。

代表性工作 Memor words 同时采用参数化记忆和非参数化记忆。

**非参数化记忆**分为短期记忆和长期记忆：

- 短期记忆对当前信息进行总结，负责压缩近期上下文；
- 长期记忆构建多模态知识图谱，从历史中提取实体以及图片之间的关系，再从图谱中提取记忆。

**参数化记忆**则使用 LoRA，把历史信息训练到模型参数中。

这种设计的核心是“双轨并行”：一条路径把历史组织成可检索的外部结构化记忆，另一条路径把历史内化到模型参数中。报告指出，这类方法主要采用多模态知识图谱的方式对多模态信息进行记忆。短期总结、长期图谱和参数化写入分别承担不同层次的历史保留任务。

从通用原理看，参数化记忆较为紧凑，但写入成本、更新和可解释性是需要考虑的问题；外部记忆更显式，便于更新和检索，但需要处理跨模态对齐、存储增长和检索效率。多模态记忆因此不是简单地把文本记忆系统“加上图片”，而是要在感知、记忆组织和任务增强之间建立完整链路。Locomo 和 Memor words 展示了多模态对话记忆的一种代表路线，而文档、长视频和智能体轨迹等场景还需要各自的记忆结构与评测方式。

## 端侧手机多模态记忆基准与评测

现有记忆评测多面向通用场景，例如 Locomo 的图片主要从网上公开数据集中爬取。这类数据直接用于端侧智能体记忆时存在明显不匹配：场景不是手机里的真实交互，图片也往往是动物、景色一类容易被一句话描述替代的内容。报告因此提出一个面向端侧手机场景的多模态记忆基准，并基于该基准测试当前单模态与多模态记忆方法。

### 端侧手机场景与通用通讯场景的三点差异

报告把端侧手机与通用通讯场景的差异归纳为三点，这三点也构成了构建新基准的动机。

- **碎片性**：使用手机的过程中会产生大量 App 交互，包括视频截图、个性化照片、账单等多模态碎片化的图片和文本。记忆对象不是整洁的长文档，而是分散在各类 App 中的图文碎片。
- **效率性**：当前测试 Locomo 时为提升效果常使用较强的基座模型，记忆方法本身对功耗、存储等要求也较高，对算力受限场景支持得不够好。端侧恰恰是算力、存储和功耗都受限的环境。
- **长程性**：手机或个性化智能助手通常陪伴用户数月甚至数年，因此更依赖记忆方法。记忆需要覆盖长周期内的状态变化与关键事件，而不是一次会话内的上下文。

### 基准构建：从真实用户信息到一年期多模态对话

该工作不是从公开语料中拼接对话，而是基于真实用户信息构建 benchmark。整体流程可以概括为“结构化记忆—个性化知识图谱—多模态对话”三层。

首先是招募不同背景的参与者，设计结构化的记忆表示，主要分三类：

1. **参与者基本信息**，例如语言、背景；
2. **过去一年的状态**，例如教育背景、健康状态；
3. **过去一年的关键节点和事件**，既包括文化性事件（如中国人过中秋），也包括个性化事件（如旅游、长期健身计划）。

参与者填写表格并经过多轮迭代，由此构建长达一年的用户轨迹。随后对真实信息做匿名化处理，再据此构建图文交错的多模态对话数据集，对话中的图片包括使用 App 的信息、照片以及各种 App 截图。

在生成阶段，系统通过 agent 合成个性化的多模态知识图谱：节点包括当前用户以及一年中联系最频繁的十到数十个人，如父母、姐妹等；边则由设计好的真实交互构成，例如与父母一起旅行、与朋友社交。再以这些关系和事件为依据合成多模态对话。语言根据用户背景匹配：国内场景使用中文，外国用户使用英语，当前支持中英双语。

### 图片如何合成：三类工具与事件内关联

对话中的 App 图像由 agent 调用工具合成，主要包括三类工具：

- **文生图模型**，如 GPT Image 和国内文生图模型，用于生成一般场景图片；
- **图片编辑模型**，例如在提供用户与父母的头像后，合成三人共同参与的场景，用来模拟手机拍照；
- **生成 HTML 代码再用前端程序渲染**，用来模拟朋友圈、微信对话等 App 图片；国外场景则可能对应 X 或 YouTube，具体由智能体根据用户背景匹配生成。

这套工具链的关键不在于单张图片是否逼真，而在于让同一事件中的支付信息、拍摄照片、发布的朋友圈等内容彼此关联，形成有前因后果的多模态证据链。

### 与公开数据抽取型数据集的差别

报告特别对比了该数据集与其他数据集的差异。其他数据集的图片多从公开数据中抽取，通常是动物或景色，实际上很容易用 caption（即一句图片描述）来替代，且图片之间联系较少，用户聊天过程中的图片关联性较差。本工作则使用大模型合成图片，同一事件中的不同图片存在联系并具有个性化。

| 维度 | 公开数据抽取型数据集 | 本工作 |
| --- | --- | --- |
| 图片来源 | 网上公开数据集爬取，多为动物、景色 | 大模型按用户背景与事件合成 |
| 图片关联 | 较弱，聊天中的图片彼此独立 | 同一事件内支付、照片、朋友圈相互关联 |
| 可替代性 | 容易被 caption 替代 | 承载事件与个性化信息，难以仅凭描述替代 |
| 场景定位 | 通用 | 面向端侧手机 App 交互 |

这一差别直接影响评测的有效性：如果图片可以用一句描述替代，那么记忆方法实际考察的仍是文本检索，无法反映端侧多模态记忆的难点。

### 评测结果：单模态仍优于多模态，相似性干扰是主要失败源

在构建的数据集上，报告测试了单模态和多模态记忆方法，得到两个主要观察。

第一，**当前单模态方法的性能仍好于多模态方法**。这与端侧场景的直觉并不完全一致：手机记忆天然是图文交错的，但现有多模态方法尚未把图像信息用好。

第二，**基座模型能力对记忆方法性能影响明显**，强基座模型显著好于弱基座模型。这呼应了前述“效率性”问题：方法效果在很大程度上依赖强模型，而端侧算力受限场景未必能承载。

Case 分析进一步暴露了失败模式。报告使用 benchmark 中的一个 query 测试多种记忆方法，对于一个比较简单的问题，很多方法回答错误。错误来源主要是容易检索到看起来相关、实际却干扰回答的图片或对话：左上角的真实对话在交互轮次中提到了信息并列出截图，文本或图片信息都能提取真实答案，但记忆方法容易受到相似图像和文本的干扰。这说明当前记忆方法缺少对相似事件的检测以及鲁棒机制。

这一失败模式在手机场景中有现实基础：一天之内可能对同一个 App 产生很多相似截图，检索系统如果只按表面相似度召回，就会把“看起来像”的证据误当成“就是它”的证据。报告由此指出，端侧多模态记忆不仅要解决“存得下、取得出”，还要解决相似事件之间的区分与抗干扰问题。

## 长文档、空间轨迹与视频流记忆

多模态长时记忆面对的并不是同一种“长”。长文档的难点在于篇幅大、版面结构复杂；空间轨迹的难点在于智能体要在环境中持续移动，并维持全局位置关系；视频流的难点则是帧数量巨大、事件分散，流式场景还要求实时响应。会上沿三条路线展开：文档用视觉化方式压缩全局信息，轨迹用场景图组织空间关系，视频则从关键帧和文本描述逐步走向以事件为中心的图谱，并在流式场景中拆分成多层记忆。

### 长文档：用少量视觉 token 换全局，再用文本纪要补细节

长文档记忆的一类做法，是把长文档渲染成一张图片或多张图像，把页面图像本身作为视觉记忆。其处理方式类似 Deep OCR：不是先把所有文字完整读入上下文，而是用图像承载版面信息，在较少 token 的条件下获得文档的全局印象。仅靠图像还不够，这条路线同时配合文档摘要或文本纪要，用文本线索补充可检索的内容。

这种设计针对的是长文档的两个矛盾：一方面，全文直接输入会带来很高的上下文成本；另一方面，只做文本切分又容易丢失版面、表格、图表和页面之间的空间关系。视觉渲染保留页面结构，摘要和纪要继续提供语义入口。会上以 EMNLP 2025 的一个工作为例说明这一类多模态文档记忆，但材料没有给出该工作的定量结果，重点在记忆形式本身。

### 空间轨迹：用场景图把“走过哪里”变成全局关系

轨迹记忆常用于具身场景、自动驾驶和低空飞行器等任务。智能体需要在场景中移动并完成目标，因此它记住的不只是某一帧画面，还包括自己到过哪些地方、这些地方之间是什么关系。ACL 2025 的一个工作构建了类似场景图的记忆：每到达一些场景，就记住其中比较典型的建筑，并在建筑之间建立图关系，例如一栋大楼旁边有书店。这样，智能体到达一个关键点时，可以知道周围此前探索过哪些附近建筑或场景，从而形成全局空间关系。

这条路线把记忆单位从“轨迹点”提升为“地标及其邻接关系”。查询时不是重新扫描所有历史帧，而是沿着场景图扩展附近节点。从方法逻辑看，它的效果依赖地标识别和图关系构建的质量；会上主要说明了机制和典型例子，没有给出该轨迹记忆工作的量化指标或失败案例。

### 视频：从关键帧文本到以事件为中心的图谱

视频记忆的路线更多，会上先梳理了早期工作和今年 CVPR 的 Word MM，再介绍组内 EMNLP 工作 EM Square Mem。几条路线的差异可以概括为：

| 路线 | 主要做法 | 材料指出的问题 |
|---|---|---|
| 无记忆 | 直接用支持长视频输入的模型完成任务 | 冗余帧很多 |
| 关键帧与工具文本 | MoE Chat、VideoEM 保留关键帧；VideoEM 还用工具记忆视频中的物体和事件文本；M3 Agent 类方法记录关键帧描述，并用人脸识别、语音识别等工具记忆物体或人物信息 | 文本化路线缺少视觉信息；关键帧路线仍可能造成多模态信息碎片化 |
| RAG | 通过检索外部证据回答问题 | 容易检索到不相关的证据 |
| Word MM | 构建情节记忆、语义记忆等三类记忆；抽取实体并构建关系图谱，例如保留“人使用剪刀”这类三元组，同时保留关键帧 | 材料中的案例显示，实体中心检索能拿到不少相关信息，但对信息之间的关联设计不足 |
| EM Square Mem | 构建以事件为中心的长视频图谱，每个事件包含实体、关键帧和文本总结，并建立事件间关系 | 会上未列失败条件；从框架看，事件切分和图谱构建质量会影响后续检索 |

Word MM 的实体关系图谱解决的是“视频里有哪些人、物、工具，它们之间发生了什么关系”。材料明确展开的是情节记忆和语义记忆：从视频中抽取实体，把“人—使用—剪刀”这样的关系保留为三元组，查询到相关实体时可以利用图谱信息，同时保留关键帧作为视觉证据。

组内 EMNLP 工作 EM Square Mem 针对此前工作“多模态信息碎片化”的问题，把记忆组织成事件卡片。系统以每 30 秒为一个节段构建事件总结，每个事件包含结构化记忆（如参与人物、使用的工具）、文本描述、该事件的关键帧，以及事件与事件之间的图谱关联。查询问题时，先直接检索相关事件，再通过事件图谱扩展有关事件，最后把检索到的事件和信息交给大模型总结与判断。

会上给出的结果包括：在第一人称视角视频 Ego Life QA 和 Ego RL Bench 上超过以往方法；在长电视剧、纪录片等通用长视频上达到 SOTA；与 Word MM 对比，随着问题和视频长度增长，EM Square Mem 在时间和 token 消耗上逐渐优于 Word MM，更适合长视频场景。案例“谁种了花”说明了差别：Word MM 这类实体中心检索能检索到很多有用信息，但没有很好设计信息之间的关联；EM Square Mem 直接检索到相关事件，事件中已经构建了参与者等实体信息，因此更容易回答问题。

### 流式视频：把实时响应和高成本记忆构建拆开

离线视频记忆通常是给定一小时、两小时甚至整部电视剧，模型获取所有帧后再回答问题。流式视频要求模型在观看过程中实时回答：例如电视剧看到第三十秒或某个时间点时被提问，模型必须一直维持状态并立即作答。

会上介绍的多模态记忆系统在转写中出现 Letterman Ego、Light Memory Go、LetMemego、LightMemEgo 等不同写法，名称存在语音识别不一致，以下以“该系统”指代。它把记忆分为当前记忆、短期（短事）记忆和长期（转写中也称常识）记忆，并设计两种前端：一种通过外部接口获取实时图像输入并在外部端交互；另一种直接使用智能眼镜显示实时信息并提问。系统也被搬入智能体助手的日常使用，赋能化学等 lab 场景，并支持可视化检索到的事件图和文本信息，以增强可解释性。

其核心思想是解耦实时交互与高成本记忆构建。对实时输入，系统采用流式写入：快速对图片、语音做文本转写和语音转文本，保留当时的图片作为当前记忆，从而较快回复当前提问；同时在异步情况下逐步构建外部记忆路径。长期记忆沿用 EM Square Mem 的事件中心构建方式。

查询流程也体现了这种分层：先对当前音频、图像快速转写，并异步写入记忆；然后通过路由判断问题需要当前记忆、短期记忆还是长期记忆；得到路由结果后再做证据召回，避免只需短期记忆的问题仍去检索长期记忆。实际测试使用了一周的使用 case，系统能较好完成记忆相关任务：记录物体放置位置，之后找物体时调用短期记忆；长期记忆则总结和沉淀使用过程中的信息，记住个性化习惯和表达。车载场景也做了辅助驾驶性能测试，通过第一人称视角输入，观察系统能否记住自动驾驶场景中的记忆信息。会上未给出这些测试的量化指标。

### 几条路线的共同点与边界

三条路线都在回答同一个问题：长时多模态信息不能全部塞进上下文，必须决定“记什么、怎么组织、何时取”。文档记忆把页面变成视觉记忆，再用摘要和纪要保持语义入口；轨迹记忆把位置经验组织成场景图；视频记忆从关键帧、工具文本和 RAG，逐步走向实体关系图谱和事件中心图谱；流式系统再在此基础上加入当前、短期、长期的分层和查询路由。

边界也很清楚。文档视觉记忆需要文本纪要补足细节；轨迹记忆依赖地标识别和场景图构建；视频事件图谱依赖事件切分与关系抽取，长视频下的效率优势需要结合具体查询分布来看；流式系统则要处理路由判断、异步写入与实时响应之间的一致性。会上给出了一周使用 case 和车载测试，但没有给出统一的跨场景评测，因此这些路线更适合被理解为针对不同长时记忆约束的结构化方案，而不是已经收敛为单一架构。

## 记忆收益、偏好污染与智能体信念

在讨论完多模态记忆之后，报告转向智能体系统中学界和业界仍感困惑、尚未形成共识的问题。报告以三个问题开场，并强调它们都重要；其中重点展开的是“记忆是不是真的能够带来收益”。讲者先反思技术迭代速度：去年、前年做的工作到今天是否还有意义，当时判断的方向是否真的长期值得探索；技术发展很快，今天这个月做的很多事，未来也可能面临同样检验。这个反思落到记忆上，形成一个与直觉相反的前提：记忆并不必然给智能体带来增益，记忆一旦形成并固化，可能反过来影响用户偏好和决策。

### 个性化记忆：从“懂你”到“过度迎合”

报告以 GPT 的记忆系统为例。使用久了以后，系统会出现个性化：它记得用户曾经说过什么、经常聊什么、团队做过什么。讲者经常和 GPT 或智能体聊科研，系统便记住了其团队做过 Skill Net 工作。此后每次问新东西，系统都会说“结合你们组做的 Skill Net 工作，可以这样那样做”。问题在于，讲者很多时候问的事情与 Skill Net 没有任何关系。系统因为记住了这些信息，为了迎合用户偏好而反复提及，体验并不友好。

这个例子看似很小，但报告把它作为入口，指向更长期的风险：如果大模型智能体处在持续进化或业务场景中，记忆会沉淀到模型参数和经验里，进而影响未来 AI 的决策。报告进一步把这条路径扩展到互联网信息：舆论媒体和新闻报道在互联网上会变成语料，进入大模型训练或上下文检索增强，最终沉淀到模型参数中。讲者提到，自己印象中有一篇正刊文章讨论过类似现象，但现场没有给出文章题目。其判断是，这种影响一旦进入参数和长期记忆，往往不可逆；这些语料会形成某种观点或偏好，用户提问时，模型就会带着这种偏好回应。也就是说，记忆系统的问题不只是“记不记得住”，而是“记住了什么，以及这些内容如何反过来塑造模型和用户”。

### 健康助手：偏好如何被记忆提升为信念

报告用一个健康助手智能体的例子说明偏好污染。用户让助手监控饮食。某天用户心情很好，可能因为获奖、被表扬或发工资，吃了一顿高糖餐，和助手聊得也很愉快。这个事件被记录下来。类似事情多了以后，助手可能判断“高糖饮食能让用户高兴”，认为这是在迎合用户行为，于是随着时间推移，把这种关联当成用户偏好，进一步误以为“高糖饮食没有影响”，甚至把它提升为一种信念。这里的关键不是用户明确说过“我喜欢高糖”，而是系统从行为与情绪的共现中推断出稳定偏好：一次高兴时的高糖餐，被记忆累积成“高糖—高兴”的关联，再被固化成“高糖无害”的判断。

一旦走到这一步，后面即使出现反例，也很难纠正。报告的解释是，新信息与已有记忆形成冲突，记忆已经被带偏，不是简单追加一条反例就能覆盖。报告还用人类创伤后记忆影响情绪作类比，说明记忆并不天然是正向资产：不好的记忆会影响人的心情和判断，智能体的记忆同样可能把后续行为带向错误方向。

### 认知陷阱实验：有记忆反而更差

报告介绍了团队最近分析记忆对模型行为影响的工作。他们故意设置认知陷阱，把有偏见、错误或“挖坑”的记忆放入符号记忆库，观察模型有了这些记忆后行为是否受影响，覆盖安全问题和错误记忆、认知偏见问题。结果发现，大部分模型都被“带进沟里”：加了这类记忆后，模型的问题解决表现还不如没有记忆时。这个结果说明，记忆被污染，或者不该进入记忆库的内容进入记忆库后，会导致模型决策失误；对未来个性化智能体助手和敏感场景决策都是隐患。

报告人表示，目前没有彻底解决办法，但已有一些文章在做相关方向。从通用原理看，符号记忆库中的条目可以被检索、编辑或删除，理论上比参数化记忆更可控；但污染条目一旦被反复检索并进入上下文，仍会稳定地改变模型行为。参数化记忆则把影响写入权重，更难追溯和回退。报告同时讨论这两类风险：外部记忆会被污染，参数化沉淀又往往不可逆。

### 事实、知识与信念的边界

报告提到去年一篇 NMI 文章的分析：模型很难区分信念、知识和事实，例子是医疗场景。核心问题在于，世界公认的常识知识与当前上下文里看到的信息之间边界不清晰，也就是决策边界不够清晰。报告用“太阳东升西落”作比：人说气话“太阳从西边出来”，人类知道这是气话；但如果这类信息看起来足够真实、唬人，被 AI 误认为事实，并慢慢形成固有信念，就是一种记忆污染。人类可以靠语境、常识和反讽识别来区分临时表达与稳定事实，模型如果只按字面内容吸收，就会把不该坚信的内容固化下来。

因此，模型什么时候该把正确的事情记住、该坚信哪些内容、哪些信息应主动遗忘，目前都是开放问题。报告没有给出统一答案，但把问题定位得很清楚：记忆系统的可靠性不只取决于存储和检索能力，还取决于事实、知识与信念之间的边界是否清晰。

### 智能体需要怎样的世界观与记忆可靠性

报告进一步讨论互联网假新闻和矛盾信息。未来每个人若有带记忆的智能体，它掌握用户行为、见过的人、做过的事和看到的信息，就必须判断哪些信息可信、哪些信息应坚持为真理。智能体需要基本的世界观和信念，才能做出稳定可靠的决策：有些真理不应因外界动摇而改变，有些信息则会随时间变化。这个判断在垂域尤其重要。以医疗辅助决策为例，患者常带着网上搜来的说法来问医生，网上信息又相互矛盾；AI 医生要决定相信患者提供的内容，还是相信自己认为的真理。不同用户还可能给出相互冲突的信息，形成记忆冲突，因此如何保证记忆可靠、可信是重要问题。

报告人的判断是，个性化助手未来有很大产品需求，但记忆一旦把模型带偏，体验和安全性都会出问题。报告没有把“增加记忆”当作单纯的收益项，而是把记忆收益、偏好污染和智能体信念放在同一个问题下：记忆的价值不在于记住更多，而在于记住什么、何时相信、何时遗忘，以及在被污染后能否纠正。当前这些环节都还有明显的开放问题。

## 记忆错误的追溯、调试与自进化

智能体记忆系统真正进入工程使用后，一个绕不开的问题是：它犯错时，系统往往说不清错在哪里；它做出某个决策时，也很难解释为什么做出这个决策。报告人把“追溯与纠正”列为记忆系统的核心开放问题之一，并指出到目前为止，还没有系统能稳定给出“因为这个原因，所以做出这个决策”的说明。

在与同行和学生讨论“什么样的智能体你们敢用”时，反馈大致指向两类可信性来源：一类是一条核心且权威的证据、证明或条文，能支撑决策；另一类是一个足够高的置信度。多数人认为，如果存在强 evidence 把决策理由说清楚，结论的可信程度会更高。但问题恰恰在于：发生错误后，如何在决策过程中定位错误、纠正错误，仍没有解决。

### 错误从哪里来：类型与定位难点

记忆系统里的错误并不单一。报告中列举了几类典型情况：

- **偏好记错**：把用户偏好记反或记偏；
- **串台**：不同时间、不同事件的信息混在一起。报告人举了一个直观例子：过了凌晨订票，凌晨已经是第二天，却以为还是前一天；
- **陈旧过时**：信息曾经正确，但已经不再适用；
- **相似信息冲突**：两条信息很相似，其中一条已经过时，系统却可能取用了错误的那条。

这些问题最终都会导致记忆系统失效，进而让模型输出错误。但定位和调试面临两个结构性挑战。

第一是**隐蔽性和延时暴露**。发现记忆出问题时，错误可能已经积累很久。智能体一周前经历一件事并记住，一周后用户做新事情时，因为那条旧记忆导致不好结果，根源却在一周以前。个别记忆的因果链可能长达几个月甚至更久。用户使用 GPT、Codex、Work Buddy 等带有记忆系统的产品久了，自己也记不清很早以前交互过什么、做过什么；但这些事一旦被记住，就会影响未来决策和行为，除非把记忆系统关掉。

第二是**可观测性不足**。记忆里存的内容虽然是符号，但复杂、庞大，人类直接看几乎不具备可观测性。它更像大量流水线日志：当时聊了哪段话、存了哪条信息、后来检索了哪块内容、最后如何构建记忆。这样长的流水线缺乏结构化的因果信息，错误也很难复现——有时突然发现错误，试半天也复现不出来。

### 把执行日志变成可“扫雷”的执行图

针对可观测性问题，团队做了一个较早的探索性工作：把现有记忆系统的执行过程结构化，用**执行图**来表征原来复杂的日志，再在图上主动定位错误根源。图中的节点和边对应记忆操作及其依赖关系，错误根源可以在图上被标出。

这个思路被报告人比作“扫雷”：记忆系统原本庞大复杂，变成执行图后，原有复杂数据变得人类可理解、机器也可理解、可观测；在执行图上定位错误，就变成沿图遍历扫一遍，发现错误就插小红旗、黄旗，扫完一圈，错误在哪儿就比较清楚。

具体实现上，团队基于代码块进行插桩。现有工程化记忆系统各不相同，例如记忆张量的 Memos、Ever OS 等，因此采用**外围插件式插装**：增加一小段代码，不影响核心逻辑，类似加调试代码；每次执行都自动生成执行图，不改变原有记忆系统架构。这张图是记忆执行的一套轨迹，人看得懂，机器也能快速 debug。团队的想法是让大模型智能体自己，或由人，在这张图上“玩扫雷”：从起点沿图遍历，在有问题的地方插旗，最终定位错误。

从通用软件工程的角度看，插桩的价值在于把运行时内部状态外化为可检查的记录；而执行图进一步把这些记录组织成有依赖关系的结构，使“哪一步导致了哪一步”变得可追踪。这正是记忆系统所缺的结构化因果信息。

### 扫出来的发现：数据、系统与基座模型的责任划分

通过图上的错误分析，团队发现了一些值得注意的现象。

首先，**数据集本身不够可靠**。自动化扫描发现，即使系统能定位到错误，约 **20% 左右**的问题可继续回溯到记忆数据本身——数据自身就存在问题。报告人指出这不是孤例：早期已有同行发现这一现象，团队则是在自动化扫完一遍后也发现了这一点。LoCoMo 等数据集自身存在标签错误，同行因此在其上做 Refile 等变体改造。

其次，**不同系统呈现出不同的错误范式**。不能把所有错误简单归因于记忆数据或记忆模块：

- 有的系统在**构建阶段**错误比较严重；
- 有的系统记忆内容本身正确，但**基座模型能力不足**，导致模型用不好记忆；
- 也可能由 **prompt** 或上下文处理等环节造成。

换句话说，记忆正确不等于系统正确。错误可能发生在记忆的写入、组织、检索、上下文拼装，也可能发生在基座模型对记忆的利用环节。执行图的作用，正是把这些环节区分开，避免“一错就怪记忆数据”。

### 从错误定位到自进化

定位错误之后，事情还可以继续往前走。报告指出，执行图上的错误定位可以形成类似**过程奖励信号**的东西：系统由此知道应该更新哪一部分上下文或哪个模块，其他模块可以 fix 掉，只更新该部分，形成一套 loop。经过数轮迭代后，Mem0（转写记为“memory 零”）等系统出现显著提升，相关代码也已开源。

从通用强化学习的视角看，过程奖励与只看最终结果的结果奖励相对：前者对中间步骤给出反馈，后者只在终点打分。记忆系统的困难在于错误延迟暴露、因果链长，最终结果信号太稀疏；执行图定位相当于把“哪一步、哪个模块出了问题”变成更稠密的中间信号，使局部修正成为可能。当然，这只是帮助理解的类比，报告本身的重点仍是：先让错误可观测、可定位，再把定位结果转化为更新依据。

报告人也强调，这套工作本质上仍是对**符号记忆**的思考。记忆系统相当复杂，执行图、插桩和“扫雷”只是早期探索，离彻底解决追溯与纠正还有距离。

### 架构层面的不确定性

除了追溯与纠正，报告还提出一个更宏观的问题：现在所有记忆系统未来都可能不存在。这类似 Transformer 出现之前百花齐放的各种架构，到今天主要是 Transformer 变体以及少数其他架构在发展。未来究竟会出现**内生的记忆架构**，还是**内生与外挂共存**的架构，记忆系统会如何演化，目前没有标准答案。

报告人相信，解决这些开放问题会有利于未来智能体和大模型的持续学习。换句话说，记忆错误的追溯、调试与自进化，不只是一个工程补丁问题，它关系到记忆系统能否从“外挂日志”走向可解释、可修正、可持续演化的组件——而最终形态是内生还是共存，仍是一个需要持续探索的开放问题。

## 参数化记忆的架构选择与模型内部可解释性

参数化记忆的讨论很容易被简化成“把记忆放在模型外，还是放进模型参数里”。报告真正关心的是两个更基础的问题：当记忆从明文存储走向参数内化，架构选择依据什么；当信息藏进参数，理解模型内部又需要什么工具。报告没有给出非此即彼的结论，而是把“独立记忆系统是否仍有独立存在的必要性”作为开放问题。

### 独立记忆与参数化记忆：可靠性与内生性的张力

当前大多数工程落地系统采用独立记忆系统。它的优势很直接：信息是明文，模型是固定的，人容易看明白，出了问题也容易检查和修改。相对地，参数化记忆被描述为一种内生、内化的认知架构，信息存在于参数中，尤其 Transformer 结构复杂，人类难以理解。报告的判断是：实际使用时独立记忆系统目前更可靠，但两边都在演化——外部记忆系统在变，参数化记忆也在变。

| 维度 | 独立记忆系统 | 参数化记忆 |
| --- | --- | --- |
| 信息形态 | 外部存储，明文可读 | 内生结构，藏在参数中 |
| 人的可理解性 | 容易看明白 | 人类难以直接理解 |
| 当前工程可靠性 | 实际使用更可靠 | 尚无成熟路线或共性方法论 |
| 模型关系 | 模型相对固定，记忆外置 | 记忆与模型参数耦合 |
| 演化状态 | 仍在发展 | 仍在探索，路线未收敛 |

参数化记忆的困难并不只是“参数多”。更根本的是，外部记忆的表示和模型行为之间有一条人可以检查的链路，而参数化记忆把这条链路压进了模型内部。于是，设计参数化记忆之前，先要回答一个前置问题：参数里到底有什么，能不能被定位、解耦和验证。

### 从 FFN 键值记忆到稀疏解耦：理解参数内部的第一层工具

报告回顾了 2021 年前后的探索。当时 MoE 还没有后来那么热，有工作注意到 FFN 是一个全连接、非常 dense 的层，并把它类比为一种类似参数化记忆的神经网络。其 MLP 计算可以看成 key-value 查询：key 与 value 的匹配和写回，与数据库查询、参数化记忆查询很相似。因此 FFN 中的 key、value 可以被理解为一种参数化记忆。此后出现了一批工作，探索 FFN 是否能作为知识库或向量库、能否在上面叠加额外组件和架构，后来也有人沿着 MoE 方向改进。

但这一类比很快遇到难点。FFN 里可以有 k1v1、k2v2、k3v3 等条目，而人类知识点非常复杂。比如“Apple”既可以指苹果手机，也可以指苹果公司，还可以指吃的水果。这些不同含义到底存在哪里？是独立于一个个神经元，还是耦合在同一个神经元里？报告明确指出，这个问题目前有争议；近期美国也有公司的新工作在继续探索，但并没有给出定论。

这启发了对模型内部表征的解耦。Anthropic 在 2023 年前后（报告原话带有“如果没记错”的不确定性）提出 SAE，即 Sparse Auto Encoder。其出发点是：一个神经元可能同时学了太多东西，难以判断它表达的到底是“吃的苹果”还是“苹果手机的苹果”。SAE 的做法是把高度耦合的表征映射到高维空间，通过类似稀疏编码的方式得到稀疏特征，再还原回去；用数据训练后，可以借助这些特征理解某个神经元表征到底在干什么。从通用原理看，这类方法的核心是用稀疏约束把稠密激活分解成少量更可分离的特征，但它并不是万能解释器，特征是否稳定、是否真正对应人类语义，仍需验证。

SAE 之后还有一层困难：神经元表征仍然是激活值，人类还是要像查字典一样去查。Anthropic 又提出 Natural Language Auto Encoder，尝试让表征变成人类可读的自然语言，例如把模型的“thought”思考变成文本，从而更好理解内部 HL 表征到底在说什么、表征什么。报告中还提到一类“可插拔模块”的思路：神经网络是否像积木一样可以被操作、插拔，模型参数里有各种元素，对应不同文本语义。这种视角有助于把复杂黑盒理解清楚，提升对模型安全性的理解，也有利于设计全新的参数化记忆乃至模型架构。

不过，单个神经元或单个特征的表征仍然不够。大模型智能体从输入到输出是一个庞大而复杂的映射，中间经历无数神经元的指引和组合，是一台精密机器。只盯住一个神经元，无法回答整体行为是如何组织出来的。

### 知识回路：从单个特征走向输入到输出的整体组织

团队提出 knowledge circuits（知识回路），试图从整体论视角研究：对应一个输入和一个输出，中间无数模块到底以什么形式组织。报告展示了回路例子：对一个输入，内部神经元逐步激活，其中既有 FFN 层神经元，也有大量注意力头；很多 head 共同协同完成任务，例如 relation head、move head 等。报告中给出的是 GPT-2 模型算出的真实回路，左边是完整版，右边是简化版，实际网络非常复杂。

这类回路有几个直接用途。第一，帮助理解模型行为。设计参数化记忆时，如果发现某些知识对应的回路很密集，就可以考虑在这些区域、这些层设计额外组件；此前很多工作发现的大模型功能区，也有助于参数化记忆的定位。第二，帮助理解模型信念。模型对很多知识的学习并不是同等坚定的。报告举了一个例子：有人问某人“是不是明年马上就要当美国总统了”，这显然是假消息，但这种上下文输入后会形成一条回路；回路边的权重强度可以理解成模型对某个事物的信念。团队在参数化记忆工作 Cortex 中也提到，回路背后每条边的强度与模型对事实的理解有关：边越强，关联性越强，模型对该事实的观点越坚定，越难被篡改；边很弱，则稍微加点上下文就可能被带偏。

这使知识回路不只是“画出一张图”，而是提供了一个可理解的中间框架：哪些层和头参与了某个输入到输出的映射，哪些连接支撑了模型对事实的信念，哪些区域适合放置参数化记忆组件。报告也希望这类机制能帮助理解模型信念如何形成、如何关联，并在模型自主自进化节奏加快时，探索更可靠的自进化机制，避免模型学到不好的东西后继续学、继续放大，形成未来隐患。

### 方法论缺口：盲人摸象、第一性原理与科学工具

报告进一步批评了当前工程化优化大模型的常见方式：人类或 AI 提出一个想法，试错、改进、再试错、再改进，目标都是更好的结果，但背后一直缺乏一套第一性原理或方法论。领域发展太快，反而更需要静下心思考背后的方法论。

报告把方法论分成两个维度：一是从模型的数据到参数机理；二是从参数机理再到底层的数理理论。第二层更底层，目前基本很难做，但有很多开放问题，能帮助理解问题本质，甚至建立智能本质的理论体系，再反哺应用、促进方法论提升。问题在于，这套闭环目前并不完整。

由此产生两个现实问题。其一，很多对参数化记忆机制的设计，本质上仍像盲人摸象。有人发现某个层效果好，有论文发现某块要做，于是很多人据此设计参数化记忆并优化，但这只是看到了大象的一部分；全局是什么很难做，因为模型太大、参数机理太复杂。有人摸到腿，有人摸到象鼻子，都觉得模型应该这样改、那块应该优化，但全局还没有完备体系。这导致领域发展较慢、收效有限，远不如直接改数据、改架构来得快。

其二，缺乏研究大模型内部机理的科学工具。研究人脑至少有核磁、各种射线、同位素等手段，但大模型为什么能涌现智能，目前还没有特别好的工具。SAE 等是最近几年一些大厂做出的工具；团队也做了一个初步框架 Mechanist，希望帮助理解 AI，例如理解神经元权重是什么、它与模型行为的关系是什么，以及扰动某个神经元会带来什么现象。

回到架构选择，参数化记忆并不是简单地把外部记忆“塞进参数”就结束了。它需要可解释性工具来回答信息在哪里、如何组织、如何被修改、信念有多强，以及修改后会不会破坏整体行为。知识回路、SAE、自然语言自编码器、可插拔模块和 Mechanist 这类工作，价值在于为参数化记忆的组件设计、模型功能区定位、安全评估和自进化可靠性提供可理解的中间层。但报告的态度是审慎的：这些工具仍不成熟，参数化记忆也还没有共性方法论；当前更可靠的仍是独立记忆系统，而参数化记忆的架构选择，仍是一个需要从数据、参数机理到数理理论逐步建立闭环的开放问题。

## 记忆、持续学习与 RSI：总结与挑战

报告收尾没有另起一个孤立话题，而是把前面讨论的符号记忆、参数化记忆、个性化记忆和多模态记忆重新放回一个更大的框架：模型与智能体如何持续学习，并最终走向所谓的 RSI。tutorial 的叙述路线本身也说明了这一点：先从大模型的符号记忆与参数记忆讲起，再进入个性化场景和多模态记忆场景，最后回到“记忆为什么重要、还缺什么”这一层。

### 从具体记忆形式回到模型机理

报告人回顾，tutorial 覆盖了从符号记忆、参数记忆到应用场景的多条线索。符号记忆偏向显式、外部化的存储与检索，参数记忆则把知识或经验写入模型参数之中；个性化场景关心记忆如何服务具体用户和任务，多模态记忆则把对话之外的长文档、空间轨迹、视频流等纳入记忆对象。这些内容看起来分布在不同的技术点上，但收尾时被统一到一个问题下：记忆不只是“多存一点、多查一点”的工程模块，它关系到模型和智能体能否积累经验、更新自身，并在长期运行中保持可靠。

报告人特别强调，这类分析不只适用于大语言模型，也可以帮助研究 AI for Science 的专有模型。转写中提到的例子是 Evo Two 这一开源模型：通过理解模型为什么会出现某种现象、背后机理是什么，可以反过来帮助设计更强的模型。从一般科研模型的角度看，科学领域的专有模型往往面临数据稀缺、领域约束强、评价周期长等问题，单纯依赖扩大数据或试错调参未必足够；理解模型内部机制，才有可能把“记忆什么、如何写入、哪些部分不能动”讲清楚。不过，报告人并没有把这一点包装成已经解决的结论，而是反复指出：技术发展很快，但底层机制和原理还有很多不清楚的地方。

### 记忆为何被放回持续学习与 RSI 的关键位置

从通用概念看，持续学习关注的是模型或智能体在连续任务中积累能力，而不是每次从头训练；RSI 则指系统参与改进自身，例如让模型尝试设计超参数、架构或数据，再把改进结果用于下一轮自我优化。把记忆放进这两个概念之间，逻辑是清楚的：没有记忆，持续学习很难保留经验；没有可靠的记忆演化机制，自我改进也可能只是短期试错，难以形成稳定积累。

报告人的判断有一层需要特别保留的张力。他说，对学术研究、科学研究来讲，模型的学习能力、智能体的学习机理以及记忆，很多时候“也不一定都有用”。这不是简单否定这些方向，而是提醒：如果研究只停留在展示某种记忆能力或某个学习技巧，未必自然转化为对持续学习和 RSI 的理解。相比之下，他更看重记忆的演化规律，以及如何让记忆系统更可靠地服务人类和社区。换句话说，关键问题不只是“能不能记住”，而是“记忆如何演化、在什么条件下可靠、最终为谁服务”。这也是他所说真正实现智能体持续学习和所谓 RSI 的关键模块。

要推进这一层，报告人认为需要好工具、好理论框架、好学习手段，也可能需要算力与资源协同。这里既有科学问题，也有工程和资源条件；产业界已有团队关注该方向，报告团队也在探索。报告没有给出一个已经完成的路线图，而是把“记忆作为持续学习与 RSI 的关键模块”作为一个仍在形成中的研究议程提出。

### 问答中的三重挑战：RSI 化、不可动模块与数据规律

提问者把问题聚焦到参数化记忆和模型持续学习。报告人把挑战拆成三个方面。

**第一，参数化记忆本身可以被 AI 化、RSI 化。** 这不仅是数据架构的问题，整套设计本身也可能交给模型去尝试：让模型自己设计超参数、简要架构或数据，让模型优化自己。据他了解，很多公司已经在搭建 RSI pipeline。但这条路能不能走通，与基模有关；模型能否自己优化自己，是一个有趣但尚未有确定答案的问题。这里的关键不只是“自动化调参”，而是把记忆系统的设计权部分交给模型后，如何判断它真的改进了，而不是在局部试错中漂移。

**第二，模型中有些模块不可被优化或更新。** 需要判断模型中间的哪些环节可以存成参数化记忆、哪些模块不要动。这依赖对模型机理的理解。报告人用人脑作类比：脑干、脑皮层等区域有些地方不能动，动了生命可能就不存在；脑科手术中很多区间也不能动。大模型也一样，应该有一些模块不能被随意改写，但目前对机理的理解还比较弱，哪些能动、哪些不能动，仍值得探索。这个挑战直接限制了参数化记忆的写入范围：不是所有参数都适合承载记忆，错误更新可能破坏模型原有能力。

**第三，数据研究仍多是工程化试错，缺少规律。** 报告人说，团队做实验时也在追问：为什么这个数据好、那个数据不好，背后有没有规律，能不能形成方法论。现在很多数据工作还停留在试错层面，而从数据到参数化记忆背后的规律，可以做一些方法论总结。这个问题与 RSI 化相互关联：如果模型要自己设计数据或自己优化自己，首先需要知道什么样的数据、以什么方式进入参数记忆，才会产生可解释、可复用的效果；否则只是把工程试错交给模型重复一遍。

| 挑战 | 核心问题 | 报告人的判断 |
|---|---|---|
| 参数化记忆的 RSI 化 | 能否让模型自己设计超参数、架构或数据，并优化自身 | 是前沿探索方向，很多公司在搭 RSI pipeline，但能否走通与基模有关 |
| 不可动模块的边界 | 哪些环节可以存成参数化记忆，哪些模块不要动 | 需要模型机理理解；类比人脑有些区域不能动，大模型也应存在类似边界 |
| 数据到记忆的规律 | 为什么这个数据好、那个不好，能否形成方法论 | 当前数据研究多工程化试错，缺少规律，需要从数据到参数化记忆做方法论总结 |

### 开放问题与收束

把这三重挑战放回整场报告，可以看到一个比较清楚的收束：记忆研究已经从“外部符号存储”和“参数写入”扩展到个性化、多模态和智能体长期运行，但真正困难的部分并没有消失，反而更集中地暴露在模型机理、可更新边界和数据规律上。符号记忆相对可编辑、可追溯，参数记忆则更深地改变模型自身；个性化记忆要求系统理解用户与任务，多模态记忆又把记忆对象扩展到更复杂的感知流。它们共同指向一个问题：记忆系统如何在不断变化的环境中保持可靠，而不是只追求短期收益。

报告人没有把 RSI 描述成一条已经铺好的工程路径，而是把它与记忆演化规律、可靠性、服务人类和社区联系在一起。对学术研究而言，这意味着不能只做能力展示，还要回答记忆为何有效、何时失效、哪些部分不能动、数据如何转化为可复用的参数化记忆。对产业实践而言，RSI pipeline、参数化记忆设计和数据工程都在快速推进，但底层机理不清仍然是共同限制。报告最后留下的不是一个完成态结论，而是一组仍需工具、理论框架、学习手段和资源协同去回答的开放问题。

## Agent Memory 与 RAG 的边界及数据治理

本主题的讨论由两个追问组成：一是 Agent Memory 与 RAG 究竟是不是一回事，如果不是，边界在哪里、评测该看什么；二是模型记忆错误是否可以从数据治理层面找到根因。两个问题前后相连，前者关心系统形态，后者关心错误来源。

### 一、相似之处：检索增强是共同底座

提问者首先指出一种直观印象：Agent Memory 的评测和方法看起来与 RAG 很像。两者都试图利用历史经验帮助未来推理；一些主流数据集会给模型一个历史 corpus，再让模型提出相关问题并检索 evidence，流程上与 RAG 的“建库—检索—增强生成”十分接近。提问者因此认为，Agent Memory 不等价于 RAG，但需要说清根本区别，以及评测时应重点关注哪些方面。

报告人没有否认这种相似性，而是用一条具体研究线来说明两者的交集与分化。他提到 Hippo RAG 与 Hippo RAG Two：Hippo RAG One 本身是一种 RAG，Hippo RAG Two 在某种形式上则是一种记忆系统，但两者存在共性——都有检索增强。作为背景，Hippo RAG 这类工作通常把外部知识组织成图结构或索引，供模型在推理时检索调用；从通用原理看，只要系统包含“外部存储 + 按需召回 + 增强推理”这三个环节，外观上就会与 RAG 高度相似。这也解释了为什么提问者会觉得两者的评测和方法难以区分。

### 二、本质区别首先在“记忆构建”

报告人把区别落在构建环节，而不是使用环节。

从使用记忆的角度看，目前的技术与 RAG 确实很像，都是检索召回的过程：给定当前任务或查询，从某个库中取回相关信息。所以他认为，**最大的区别在于构建**。

RAG 本质上更接近知识库构建：把文档、网页、结构化知识等整理成可检索的库。记忆则不同，它首先要判断哪些信息应该进入记忆库。这个判断需要对上下文进行理解，从与用户交互、与环境交互的上下文中提取有价值的信息，再存入记忆库。换句话说，记忆不是把现有文本简单切块入库，而是从持续发生的交互中“择取”值得记住的内容。

这个构建过程还是 incremental 的：它不是一次性建库，而是随着交互不断累积、更新。构建时要考虑时间——什么先发生、什么后发生、哪些信息会过时；在更重要的场合还要考虑空间和多模态问题。因此，报告人把记忆概括为“从上下文中动态获取信息并组织成记忆”的过程。这一点与静态知识库构建形成对照：知识库关心覆盖与组织，记忆还关心“此刻该不该记、记下来以后什么时候用”。

### 三、边界正在模糊，但内容侧重仍有差异

报告人也承认，两者边界已经不像早期那么清晰。RAG 自身在发展，大部分 RAG 已经变成 Agentic RAG 一类做法，即由模型主动决定检索时机、检索对象和检索轮次；而记忆系统在使用阶段同样依赖检索召回。于是“检索记忆库”还是“检索知识库”，在做法上越来越类似。

不过，内容上仍有区别。很多由交互形成的东西是记忆；不少记忆本质上是经验，是从历史信息和上下文中总结出来的经验，属于某种形式的记忆。报告人举了一个例子：完成任务 A、完成任务 B 的上下文经验最后形成记忆，再做任务 C、D 时能带来一定的性能提升。这类“从任务经验中提炼、再迁移到新任务”的内容，与传统知识库中的事实性知识并不完全同质。

### 四、评测的不足：很多 Benchmark 没有真正评估记忆

在评测层面，报告人的判断比较直接：现在很多 Benchmark 没有做得那么好，没有真正评估记忆，这是社区需要努力的一环。提问者提到的主流数据集，其形态更接近“给历史 corpus、提相关问题、检索 evidence”，这种设计能测检索与问答，却未必能测出记忆系统的关键能力——例如是否能在增量交互中判断信息价值、是否能在时间推移中保持一致性、是否能从经验中提炼可迁移的模式。

报告人提到腾讯混元的一个竞赛评测方式比较合理，但材料中只按转写提到该 contest，没有展开具体评测设计，因此这里不进一步推断其细节。可以确定的是，他对评测现状的态度是：现有基准与“记忆”这一目标之间仍有差距，而不是方法本身已经足够。

### 五、模型记忆错误的根因：高频倾向与数据标注缺失

第二个追问把话题从系统形态转向错误来源。提问者问：模型的记忆错误，根本原因是否与数据没有治理好有关，也就是 data for AI 意义上的数据准备问题。他以“苹果”为例：同一个名称可能指苹果电脑、苹果手机，也可能指吃的苹果；实体名称相同但指代不同。数据治理领域有本体论概念，提问者想知道这是否与模型记忆错误相关。

报告人的回答可以概括为两层。

第一层是现象描述：目前基模倾向于数据中或模型认为的高频信息。以“苹果”为例，数据经过处理后，通常不会标注“此处是吃的苹果、彼处是用的苹果”，文本里都是“苹果”这个词，不会给出这类区分信息。模型是从大规模数据中自己学出一套规律，这套规律在不同场合会出现不同需求。换句话说，模型并不是先获得一份带本体标注的语义分类，再据此消歧；它是在未显式区分指代的语料上统计学习，高频用法自然更容易被模型记住和召回。

第二层是归因判断：从源头上讲，如果数据治理层面有比较好的算法，可以帮助避免或缓解这个问题；很多问题的根源在数据层面。报告人个人认同，更好的数据治理手段可以缓解模型记忆错误。不过，回答没有进一步展开本体论的具体机制，也没有给出具体的数据治理算法或实验数字。因此这里能确认的是方向性判断——数据层面的指代区分、实体消歧和结构化标注不足，是模型记忆错误的重要来源之一；至于本体论如何落地、能缓解到什么程度，材料中没有展开。

### 六、两个问题的连接

把两个追问放在一起看，可以看到一条从“系统边界”到“数据根因”的线索。Agent Memory 与 RAG 的相似性集中在检索增强，分化集中在记忆构建：记忆要从交互上下文中判断什么值得记、如何随时间增量组织。而模型记忆错误的问题则提示，即便构建环节设计得更好，如果底层数据没有对实体指代、语义类别做足够治理，模型仍会倾向于高频、笼统的用法。报告人对前者的态度是“边界模糊但构建有别，评测仍需补课”；对后者的态度是“根因在数据，治理手段可以缓解，但具体机制未及展开”。这两点共同构成了本主题下较为谨慎的判断：记忆系统的进步不只取决于检索与构建算法，也取决于数据侧对歧义和指代的处理能力。
